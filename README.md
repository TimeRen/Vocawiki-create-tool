# Vocawiki-create-tool Vocawiki条目辅助工具

Automatically generates Wikitext for Japanese VOCALOID songs, tailored specifically for the [Vocawiki](https://voca.wiki/). If you are not a Chinese speaker, this project is probably useless to you.

本程序用于生成自动[Vocawiki](https://voca.wiki/)的日语VOCALOID歌曲条目。本仓库主体代码来自于[MGP-VJ-tool](https://github.com/lihaohong6/MGP-VJ-tool)，并在此基础上修正了一些bug并添加新功能。

## 启动方法

从[releases](https://www.github.com/TimeRen/Vocawiki-create-tool/releases) 下载程序。将压缩包解压后运行`Vocawiki-create-tool`即可使用——会直接打开图形界面窗口，不用在终端里输入。

界面分成左侧的功能竖栏与右侧的内容标签页：

| 标签页 | 作用 |
| --- | --- |
| **填写信息** | 上方是对话记录（问过什么、答了什么），下方是当前问题的输入区（输入框 / 整段粘贴 / 选项按钮）：输入框占满一整行，三颗按钮在它**右下角**——「清空」（或按 Ctrl+L）只清当前输入，「确定 / 完成」提交，红色的「清除对话记录」清掉上面整块记录（会先弹窗确认，可在设置里关掉这个弹窗）。**流程跑完（或出错结束）后，输入区会自动回到「输入框」这一页**，所以那颗红按钮任何时候都看得见——否则最后问的若是选择题，界面会停在选项页上、按钮就找不到了 |
| **日志** | 网络请求、上传进度、错误与 `print` 输出都在这里；可勾「显示调试日志」、一键复制全部内容 |
| **样式** | 可视化样式编辑器（`color.color_editor` 打开时，见下） |
| **歌词** | 歌词整理（需要手动提供歌词时出现） |
| **提交** | 实时预览 / 编辑 / 提交条目与封面（`wiki.submit_window` 打开时） |
| **设置** | 可视化改 `config.yaml` 与 `wiki_credentials.yaml`（账号 / AI 密钥）。**平时不在标签栏上**，点侧栏齿轮才出现；保存成功或切到别的标签页后自动收回去 |

「样式」/「歌词」/「提交」三页平时是灰的（点不动），流程走到那一步会自动点亮并切过去。

左侧竖栏是功能入口（配色与排版参考 MediaWiki 的 [Timeless](https://www.mediawiki.org/wiki/Skin:Timeless) 皮肤）：

- **功能**：目前只有「生成歌曲条目」，以后加新功能就加在这里；选中项是白底 + 左边一条蓝条，鼠标悬停有说明。
- **头像**：点一下登录 Vocawiki。登录后显示你自己的头像，右下角小圆点表示登录状态（绿 = 已登录）；已登录时再点会弹出菜单：重新登录 / 退出登录 / 账号与密钥设置。
- **齿轮**：打开「设置」页（配置 / 账号 / AI 密钥）。
窗口底部还有一条状态栏，显示现在进行到哪一步。报错太长时这里只显示冒号前那半句（比如「网络请求失败」），把鼠标移到上面才会显示括号里的完整信息。

窗口大小随便拖：拖窄到装不下时，当前这一页会自己冒出滚动条，按钮不会被挤出可视范围。

想回到纯终端的老用法：`Vocawiki-create-tool --console`（或在命令行里加这个参数），问答就会照旧打印到控制台。

## 使用方法

程序会自动输出需要的信息，往里面填就行。

正常流程：
1. 提供日语曲名（必填）
2. 提供中文曲名（如果与日语曲名一样或没有翻译则留空）
3. 提供B站视频链接（如有）。如果填了，程序会询问视频是否是亲自投稿。这里可以直接粘手机端分享出来的 `https://b23.tv/xxxxxxx` 短链（`bili2233.cn` 也认），程序会自动跳转一次换成真实链接；如果短链其实指向图文 / 笔记而不是视频，会提示重新输入。
4. 参加了 The VOCALOID Collection 时，**赛道与名次不用自己填**：程序会去爬那一届的活动模板（如 `Template:The VOCALOID Collection2022春`）现读 —— 每个赛道一个子导航框（`TOP100` / `ROOKIE` / `REMIX`），榜单按名次分段（`61-70位`）、段内按名次排列，所以「第几名」是算得出来的；**多个赛道都在就都写**（参 涅槃(HotaRu)：`获得TOP100中的第'''70'''名、ROOKIE榜中的第42名`；REMIX 写成 `Remix榜中的第'''1'''名`，参 `Relay Outer/Iyowa`），哪个赛道都没有（包括列在「其他歌曲 / 未上榜歌曲」里）就按榜外处理、不写名次。活动模板取不到（不存在 / 网络失败 —— 实测 2023秋 / 2024春 / 2024夏 / 2025春 这几届 wiki 上就没有模板）时才会弹出来问你，那时可以选 TOP100 / ROOKIE / REMIX / 榜外。

通过修改`config.yaml`文件（或在界面里点侧栏底部的齿轮可视化改，见「设置页」一节），可以解锁以下功能：
1. 询问是否有投稿文。如果输入投稿文，则需要输入多行内容，结束时输入空行告诉程序输入停止。
2. 启用可视化样式编辑器：自动载入封面，可直接用吸管在封面上取色，并实时修改`VOCALOID_Songbox`三行颜色；面板分为 Songbox / Introduction / 歌词 三段——后两段支持与矩形同样的背景、边框、圆角、阴影、文字样式等设置，分别写入`VOCALOID Songbox Introduction`（`lbgcolor` / `ltcolor`，带额外声明时自动补`rbdcolor`）与`LyricsKai`（`lstyle` / `rstyle` / `containerstyle`，每项都可用「输出」开关控制是否写入代码）。标签格跟别的不同：它没有独立的参数放这些设置，所以盒子相关的（`padding` / `border` / `border-radius` / `box-shadow` / 渐变）会跟在`lbgcolor`的颜色后面，文字相关的（`font-size` / `font-weight` / `letter-spacing` / `text-shadow`）跟在`ltcolor`后面，站内真实条目就是这么写的（参`涅槃(HotaRu)`）。
3. 自动处理中日对照的翻译。
4. 自动下载分辨率最大的封面图（先只看图片头部识别尺寸，下载后再复核一次真实分辨率，糊图会依次换下一个来源；niconico 的缩略图会自动换成带`.L`的大图）。
5. 生成条目后自动切到「提交」页，可实时预览、修改并直接提交到 Vocawiki，同时一并上传封面（见下）。
6. 以及其它默认打开的功能，如裁剪封面图片的黑边。

## 歌姬名与分工栏（`VOCALOID Songbox Introduction`）

- **歌姬名先归一化**：VocaDB 上的声库全名（`初音ミク V4X (Original)`、`Synthesizer V AI Megpoid`、`KAITO V3 (Unknown)`）会先砍掉声库 / 版本后缀再写进条目，这样歌姬栏、引擎（`[[Synthesizer V]]`）、歌手分类（`[[分类:Megpoid歌曲]]`）才对得上；
- **链接按站内惯例写**：默认用中文页名（`[[初音未来]]`），条目名与显示名不同的按对照表写，例：GUMI 写成`[[Megpoid|GUMI]]`（参[视力检查](https://voca.wiki/视力检查)）；
- **同一个人占了两栏就并成一栏**：「曲绘」与「PV制作」是同一个人 → 并成一栏`曲绘、PV制作`（参[学习室](https://voca.wiki/学习室)）；「编曲」的人本来就已经写在「词曲」里 → 不再单开一栏（参[小小星座](https://voca.wiki/小小星座)）。分开两个人时照旧各写各的。

## 非公開 / 已删稿的 niconico 视频（用 nicolog 补全）

作者隐退、版权下架等原因把视频改成**非公開**（或直接删掉）后，niconico 的接口就再也取不到投稿日期和播放量了。这时程序会自动改用第三方存档站[ニコログ](https://www.nicolog.jp/)（`utils/nicolog.py`）把数据捞回来：

- **触发条件**：niconico 侧解析出的投稿日期为 0（接口查不到 / 页面 404）；
- **补全内容**：投稿日期、**最终记录的播放量**、标题（封面见下）；
- **输出变化**：Songbox 不再写 `|nnd_id` / `|nnd_date`，改用投稿列表：

  ```
  |投稿 =
  {{VOCALOID_Songbox/card|nnd|sm16693848|2012年1月14日|再生=1,081,622|class=deleted}}
  ```

  `class=deleted` 会让模板自动补上「**最终记录**」的角标，并照常生成「2012年投稿至niconico的歌曲」「1月14日投稿至niconico的歌曲」这类分类（参考条目：[杰西卡](https://voca.wiki/杰西卡)）。日期写`2012年1月14日`或`2012-01-14`、播放量参数写`再生=`或`count=`效果完全一样，模块都认。
- **播量仍然算数**：捞回来的最终播放量会正常参与荣誉题头（`nrank` 殿堂 / 传说 / 神话）计算，所以已下架的百万曲不会丢掉题头；
- **多平台**：同一首歌在 B 站 / YouTube 还有活着的版本时，会各占一行一起列进`|投稿 =`，只有那个非公開的 niconico 版本带`class=deleted`；
- **封面拿不到**：nicolog 记的封面是 niconico CDN 上的列表小图（默认只有 130x100），程序会先换成带`.L`的大图（360x270），并按分辨率与同一首歌其它平台（B 站 / YouTube）的封面比大小，挑最清晰的那张，都没有时就在提交页里手动处理；
- **局限**：nicolog 只收录 niconico；它记的是「最后一次抓到的数字」，可能与 wiki 上手抄冻结的数值差几百（如杰西卡 1,081,622 vs 1,081,660）；太冷门或刚删的视频可能没有任何存档，这时行为与以前一致，只在日志里给一条警告。

这个功能默认开启，不需要改配置。

## 人声本家（同一首歌的人声演唱版本）

把`config.yaml`里的`wikitext.human_original`设为`true`后，程序在探测完同名条目后会多问一句「**是否存在人声本家**（同一首歌的人声演唱版本）？」，回答「是」再依次要两个链接（都可以留空跳过）：

1. 人声本家的 **niconico 或 YouTube 链接**；
2. 人声本家的 **bilibili 链接**。

可以整条网址直接粘（`https://www.nicovideo.jp/watch/sm27831783`、`https://youtu.be/TG9IjsxAWUs`、`https://www.bilibili.com/video/BV1Jv411N7Wn`），也可以只填 `sm27831783` / `TG9IjsxAWUs` / `BV1Jv411N7Wn` 这样的 ID（B 站那边同样支持 `b23.tv` 短链，程序会自己跳转解析）；站点认不出来时会提示重填，一直留空就是跳过（两个都留空 = 没有人声本家）。这里只按链接解析站点与 ID，不会联网去取它的播放量，所以填错视频号也不会把条目别的字段带歪。

开启后条目会有两处变化（参考条目：[如月车站](https://voca.wiki/如月车站)、[红色房间](https://voca.wiki/红色房间)）：

- **简介**里多一句「另有P主本人演唱的人声本家。」（单独一段，排在活动 / 专辑那句**后面**）。如果演唱的其实是别的唱见，在提交页里改这一句就行；
- **「== 歌曲 ==」小节**按版本分块，各版本的视频不再混在一起：

  ```
  == 歌曲 ==
  {{VOCALOID Songbox Introduction
  …
  }}

  ;VOCALOID本家
  {{bilibiliVideo|id=BV1nv411N7mY}}

  ;人声本家
  {{BilibiliVideo|id=BV1Jv411N7Wn}}
  ```

  - 本家那一块的标签跟着歌姬的引擎走（`;VOCALOID本家` / `;CeVIO本家` / `;UTA本家`…）；
  - **有 B 站稿件就只写 B 站那一个**（即便这份人声本家还挂在 niconico / YouTube 上，参[红色房间](https://voca.wiki/红色房间) / [如月车站](https://voca.wiki/如月车站) / [小小星座](https://voca.wiki/小小星座)）；一个 B 站稿件都没有时才退回 nico / YouTube 的写法；
  - 本家没有 B 站稿件时只出「`;人声本家`」那一块；人声本家没填任何链接时整个功能等于没开；
  - niconico 没有播放器模板，用站内已有的`{{sm|sm27831783}}`生成链接；YouTube 用`{{YoutubeVideo}}`（模板自带「中国内地无法播放」提示），B 站用`{{BilibiliVideo}}`。

## 其他版本（同一首歌的翻唱 / 改编版本）

`config.yaml` 里 `wikitext.other_versions` **默认开启**（设置页「Wikitext」组里也能勾）。开启后，程序从 VocaDB 拿到这首歌的 `alternateVersions`（同一个原曲下面挂着的翻唱 / 重编曲版本），列出来让你挑：

```
要把哪些其他版本也写进这个条目？（选一个加进来，最后一项 = 不加了）
1: 镜音铃版｜じゃがりこP feat. 鏡音リン｜2007-12-28
2: 重音Teto UTAU版｜tattoo2003 feat. 重音テト｜2008-04-06
3: 不加了，就这些
```

选中一个之后依次问（参考条目：[鸟之诗](https://voca.wiki/鸟之诗)）：

1. **该版本的 bilibili 链接**（只收 B 站链接 / BV 号，留空就跳过这个版本）；
2. **「B 站投稿是P主自己提交的吗？」**——回答「否」的算转载，播放量再高也不计殿堂。

**简介是自动生成的，和主简介同一套句式**（`main.intro_sentence()`，两边共用）：

```
《'''{{lj|鳥の詩}}'''》（鸟之诗）是由{{lj|[[じゃがりこP]]}}于2007年12月28日投稿至[[bilibili]]的[[VOCALOID]]日语翻唱歌曲，由[[镜音铃]]演唱。
```

- 日期 / 站点：官方投稿就写「于〈该 B 站稿件的投稿日〉投稿至[[bilibili]]」；回答「不是 P主 自己提交的」时改用 VocaDB 记的投稿日与投稿站（`pvServices`），例如「于2008年4月6日投稿至[[niconico]]」—— 不把转载说成是 P主 投的；日期都取不到就写「投稿至[[站点]]」，站点也认不出就写「投稿」；
- 引擎 / 歌姬：和主条目一样按歌姬算引擎、去重（两个 VOCALOID 歌姬只写一个 `[[VOCALOID]]`）；
- 曲类：Cover → 「日语翻唱歌曲」、Remix / Arrangement → 「日语改编歌曲」（主版本是「日语原创歌曲」）；
- **活动（ボカコレ 等）**：VocaDB 上的活动是**按版本**记的（`releaseEvents`，实测同一个原曲下 589198 那个版本就单独挂着 ボカコレ2024冬），所以其他版本参加过的活动也会被检测到，简介里照主简介写「本曲参与了…活动…」，赛道 / 名次同样去爬那一届的活动模板（多个赛道都在就都写）；只有 `The VOCALOID Collection` / `ボカコレ` 这类活动会被认出来（「重音テト誕生日」这种别的活动不管）；
- **注释区的活动模板**：主版本与**各其他版本**参加过的活动都会写上，多届就多写几个模板（例：主版本 ボカコレ2024冬 + 某个版本 ボカコレ2025春 → `{{The VOCALOID Collection2024冬}}` 与 `{{The VOCALOID Collection2025春}}`）；同一届只写一遍（赛道 / 名次用主版本那份），提交窗口的「同步修改大家族模板」也按同一份清单来；
- **收录专辑**：其它版本如果被专辑收录，简介里也照主简介写一句「**本曲**收录于专辑《…》。」（专辑名取自 VocaDB 上这个版本自己的 `albums`；其他版本没有活动那句，所以主语就落在这句上 —— 主简介里参加活动时主语在「本曲参与了…活动」上，专辑那句不再重复「本曲」）；
- **同名单曲不写**：专辑名就是歌曲原名、而且整张碟只收录这一首曲子时，这张碟不写出来（「收录于专辑《ナ2モノ》」等于没说；实测 VocaDB 上 ナ2モノ 的 Single 版就只有它一首）—— 主简介与其他版本简介一视同仁，曲目数取不到时保守起见照旧写；
- 主简介里只属于**主版本**的那句（人声本家）不跟着搬过来；想手写补充就在提交页的预览里改。

选中的版本会被写进条目，结构上分两处：

- **整页套一层 `{{tabs}}`**，一个版本一个 tab（`{{标题替换}}` / 同名条目模板留在 tabs 外面）：每个 tab 里是「荣誉题头 + Songbox（演唱 / 歌曲名称 / P主 / 该版本在各站的投稿，见下）+ 简介」—— 荣誉题头按**该版本自己**的播放量算，该版本在哪个站到了殿堂就写哪个（`nrank` / `yrank` / `brank`），其中 B 站那栏是转载（回答过「不是 P主 自己提交的」）就不算；
- **tab 按钮上写短名**：主版本叫「原版」，其他版本平时就是版本名本身；只有当它需要靠补充说明才能和别的版本区分时（例如 `ナ2モノ (ROCK_VER)` 与 2024 年的重制版）tab 上才只写那一截 —— `ROCK版`、`2024年版`。**「== 歌曲 ==」里的 `;版本名` 仍是完整的版本名**；
- **其他版本自己的投稿栏**：niconico / YouTube 的稿件 ID 从 VocaDB 上那个版本的 `pvs` 取（B 站那份是你填的），按 `nnd_id` + `nnd_date`、`bb_id` + `bb_date`、`yt_id` + `yt_date` 的次序写，哪个站点没有就不写那两栏；日期取不到（站点被风控、视频已删）时退回该版本的 VocaDB 投稿日，不会写出「1970年1月1日」；
- **「== 歌曲 ==」小节**按版本分行，列出各版本的 B 站播放器：

  ```
  == 歌曲 ==
  {{VOCALOID Songbox Introduction
  …
  }}

  ;すぷいちゃん初音未来版
  {{bilibiliVideo|id=BV1nv411N7mY}}

  ;镜音铃版
  {{BilibiliVideo|id=BV1is411f772}}
  ```

细节：

- **版本名**规则是 `[P主]歌姬[ 引擎]版`——引擎和本曲不同才写（例：重音Teto 是 UTAU → 「重音Teto UTAU版」；IA 唱 VOCALOID 版本时就不写引擎）；同一批里出现重名（同一个歌姬的多个版本）时前面补上 P主区分，还是重名就再补一个括注（优先 VocaDB 版本名里多出来的那截，其次投稿年份）；
- 其他版本的**封面图与配色** VocaDB 上没有，生成时留空，需要的话在**提交页的预览里直接补**；
- 歌词 / 注释 / 分类是各版本共用的，都留在 `{{tabs}}` 外面，不会跟着版本切换；
- **一个版本都不选**（或者 VocaDB 上没有其他版本）时，输出和以前完全一样（不加 tabs）；
- 候选超过 30 个时只列前 30 个（热门曲子能有上百个版本），日志里会写明一共有多少个；
- 关掉该开关就完全不问，也不会联网取这些版本。

## 样式页的两块文本框（手改的内容不会被冲掉）

「样式」页左下角有两个可以直接写的框，**你写进去的内容不会因为操作界面而消失**：

- **`Wikitext 参数`**：三块颜色 + 模板参数的汇总输出。切右侧的「分段 / 目标」标签、改右边的控件都不会覆盖它（一旦你手改过，标题会变成「手改的内容会留着 · 点『从文本载入』让它生效」）。点「**从文本载入**」把你的文本**解析回模型**（模型 / 预览 / 右边的控件跟着变，**框里仍是你写的那份原文** —— 程序不会把它规范化重写一遍）；只有点「重置当前 / 重置全部」、**用 AI 生成（或撤销生成）**、或开始新一轮生成才会重新生成这段文本。框里认不出任何参数时（空框、贴错东西）会被拒掉并在标题上提示，不会拿默认值盖掉你刚调好的样式。
- **`完整 CSS（可编辑）`**：按编辑对象分开记。手改之后切到别的对象看别的 CSS，**切回来还是你写的那份**（标题同样会提示）；点「**应用代码**」把它应用进模型后恢复正常。保存时交给流程的一律是你看到的那份文本。

## 辅助工具（测量 / 参照物）

「样式」页右侧面板底部的「**辅助工具（测量 / 参照物）**」是纯视觉的小尺子，不参与任何输出（不会写进 wikitext）：

- **测量**：点「开始测量」后，在**预览台**或**封面图**上点两下，两点之间会画出一条蓝线，并在面板上给出「距离 xxx px（Δx / Δy）」；量完再点一下会重新开始一次测量，点「清除测量」清掉。
- **参照物**：选好「线段 / 矩形」（矩形才有「高」）、角度与宽高后点「开始放置」，再到画布上点一下就在那里放一个参照物（红色虚线，锚点用小圆点标出），最多 24 个；点「清空参照物」全清。
- 两块画布（预览台与封面图）**各记各的**，互不干扰；退出工具模式后画出来的东西会保留，方便对着尺寸调参。
- 与取色吸管**互斥**（开一个就关另一个）；`Esc` 或**右键**退出工具模式。

## AI 参考封面生成 CSS

样式编辑器面板底部有一个「**AI 参考封面生成 CSS**」按钮：把封面图与当前样式发给多模态（能看图）的 AI，让它按封面的配色与气质给出 CSS 并直接应用在编辑器里（可点「撤销这次生成」回退）。

- **生成范围**：默认**当前编辑对象**（也可以选一次生成全部：Songbox + Introduction + 歌词）；换一首歌会回到默认；
- **只改颜色**：默认**不勾选**；勾选后只允许 AI 写颜色相关属性，不碰尺寸 / 字号 / 间距；
- **补充要求**：按当前对象预填`config.yaml`里的`color.ai_prompt_songbox` / `ai_prompt_intro` / `ai_prompt_lyrics`，在 Songbox / Introduction / 歌词 之间切换时会自动换成对应那一栏的默认值；自己手写之后就不再自动覆盖（清空后才重新接管）；
- **Introduction 也照写**：AI 给标签格的 CSS 里除两个颜色之外的盒子 / 文字声明同样会进 wikitext（跟在`lbgcolor`与`ltcolor`后面，见上一节），不会被默默丢掉；

密钥与 Vocawiki 密码放在同一个文件 `wiki_credentials.yaml` 里（预设 DeepSeek-V4.1-Flash，也可填 `anthropic` 用 Anthropic 消息接口）：

```yaml
ai_provider: "openai"                          # openai = OpenAI 兼容接口
ai_base_url: "https://api.deepseek.com/v1"     # 换服务商改这里
ai_model: "deepseek-flash"                     # = DeepSeek-V4.1-Flash，必须支持看图
ai_api_key: "sk-..."
ai_thinking: false                             # 仅 DeepSeek：是否开思考模式（默认关，更快更省）
```

`ai_api_key` 为空时按钮会置灰；把`config.yaml`里的`color.ai_css`设为`false`则整个 AI 面板不显示（完全断网使用）。打包（`build.py`）时会自动清空该文件里的 `username` / `password` / `ai_api_key`，不会把密钥带到分发包里。

程序图标：把图标图片存成 **`assets/icon.png`**（正方形最好），`python build.py` 时就会自动转出多尺寸的 `assets/icon.ico` 并嵌进可执行文件（Windows）；也可以直接放一个现成的 `assets/icon.ico`。两处都没有时照常打包，只是 exe 用默认图标。

同一套密钥也给「歌词」页的「**AI 识别并填入**」用（开关是`wikitext.ai_lyrics`）；这里只发文字、不发图片，所以那个功能对模型没有「必须支持看图」的要求。开关`wikitext.furigana_all`（设置页里叫「**AI 生成振假名**」，默认关）也会用同一个模型：生成歌词时把日语里**没写读音**的汉字标成`{{photrans|汉字|假名}}`，交给你的还是原来那段歌词、只是多了注音——模型要是敢增删或改写正文，整段结果会被丢掉，只记一条日志，不影响正常生成。

密钥与服务商都在侧栏底部齿轮进的「**设置**」页里填（见下节）；样式页的 AI 面板在没配密钥时会置灰，并把原因（提示去 `wiki_credentials.yaml` 填 `ai_api_key`）写在按钮下方。

## 设置页（可视化改配置）

侧栏底部的**齿轮**（或点头像进的菜单）会打开设置页，不用再手改文件。
「设置」**平时不在标签栏上**：点齿轮才把它叫出来（切到别的标签页、或点右上角「保存」成功后，它会自己收回去），
这样标签栏里始终只留当前工作流的那几页。保存失败时会留在原地，方便看清「保存失败：…」那句。

- **基本**：界面语言、**应用字体**、输出目录、是否把输入存成文件、代理、清除对话记录前是否弹窗确认、字号是否随窗口大小缩放；
  **界面语言**选中文时，Qt 自己的文字（文本框的右键菜单「剪切 / 复制 / 粘贴 / 全选」、对话框的「确定 / 取消 / 是 / 否」）也会跟着走中文，**提交页预览里的右键菜单**（返回 / 重新载入 / 复制链接地址 / 检查元素 ……）同样换成中文（`lang: en` 则保持 Qt 与 Chromium 默认的英文；改完要重启程序才换）；
  **应用字体**那一栏点一下就弹出文件选择框：挑一个字体文件（`.ttf` / `.otf` / `.ttc`）打开，整个界面立刻换成它（没装进系统的字体也能用）；右边的「默认」换回默认字体。换完就一直用它（拖窗口改大小、缩放字号都不会把它变回去），想下次启动也用它就点「保存」——那时才会写进 `config.yaml` 的 `font_file`；点「放弃改动并重新载入」可以退回文件里记着的那一个。
- **生成内容**：P主模板 / 导航框折叠 / AI 歌词 / 人声本家 / 投稿文 / **AI 生成振假名** 等开关；
- **样式编辑器**：是否启用「样式」页、是否显示 AI 面板，以及 AI 三栏的默认提示词；
- **封面图片**：是否下载封面、是否裁黑边；
- **Vocawiki**：API 地址、提交页、日文重定向、同名条目处理；
- **账号与密钥**：`username` / `password`（点「显示」可看明文）、AI 接口类型 / 接口地址 / 模型名 / `ai_api_key` / 思考模式。

几个要点：

- 右上角的「**导入配置文件**」可以选一个（或多个）`config.yaml` / `wiki_credentials.yaml`，把里面的值填进这一页：程序按内容自己认是哪种文件（配置归配置、账号与密钥归账号与密钥），**只改界面、不写盘** —— 检查无误后再点「保存」才落到这两个文件里。文件里没写的项保持现状，所以导入一份残缺的配置也不会把其它设置清空；认不出来的文件会直接在底部红字拒绝（界面不动）。
- 点「**保存**」后写回 `config.yaml` 与 `wiki_credentials.yaml`，并**立即重新载入**（后面用到配置的地方都拿新值），随后「设置」标签页自动收回去、回到你点齿轮之前那一页；输出目录 / 保存输入这类在流程开始时读一次的，会在下一次运行时体现。
- 写回是**就地改值**：文件里的注释、顺序、其它设置都保留，不用担心被 YAML 重排；文件里缺的项会补到对应小节的末尾。
- 保存失败（比如 exe 放在没有写权限的目录）会在底部红字提示，完整原因看「日志」页。
- 密钥文件本身是明文，但打包分发时 `build.py` 会自动清空 `username` / `password` / `ai_api_key`。

## 歌词整理页（手动提取歌词）

自动找不到中文翻译时会询问是否手动输入；选「是」后自动切到主窗口的**「歌词」页**（本曲歌姬会一起带过来，下方「歌唱者标记」里直接就是 vocadb 认出来的那几位；能识别到什么程度见下面「演唱者上色」）：

- 左边粘贴整段歌词（日语 / 中文 / 罗马音混在一起也行），点「**自动识别并填入**」：
  1. 日语栏已有内容时，就以它为参照把中文行挑出来；
  2. 否则按语言逐行分类（含假名=日语、纯 ASCII=罗马音、纯汉字行按段落结构判断）；
  3. 都认不出来时，按重复段结构推测「每组行数 + 各语言行号」，再点「**按行号转换**」切分。
  - 填进日语栏之前会自动把「漢字(かんじ)」这种**括号注音**转成 `{{photrans|汉字|假名}}`（以前是单独一个设置开关，现在并进了这一步）；已经是`{{photrans}}`的地方不会再套一层。
- 右上角还有一个「**AI 识别并填入**」：把整段歌词交给大模型按语言分栏（带编号、时间轴、混排的奇怪排版用它更稳），结果直接填进三栏，仍可手动改。它只做分栏、不翻译也不改写歌词，并把「待归类歌词」和你已填的日语栏一起发给模型作为分行参照；分完栏同样会把括号注音转成`{{photrans}}`。
  - 是否**允许使用 AI** 由`config.yaml`的`wikitext.ai_lyrics`控制：设为`false`时按钮整个不显示，也不会有任何联网调用（纯规则的「自动识别并填入」照常可用）；
  - 开关开着但没在`wiki_credentials.yaml`里填`ai_api_key`时，按钮置灰，鼠标悬停能看到原因；
  - 模型 / 接口与「AI 参考封面生成 CSS」共用同一套配置（`provider` / `base_url` / `model` / `thinking`），配一次两处都能用。
- 四栏都可以手动修改，栏标题右侧实时显示行数；下方可填翻译者 / 翻译链接 / 来源 / 来源链接，这些会写进`LyricsKai`上方的翻译说明与`<ref>`。
- 填好「来源链接」后点「**从链接填充**」，会自动读页面并填好翻译者 / 翻译链接 / 来源：
  1. **网易云**歌曲链接 → 翻译者取**贡献翻译者**（`transUser`），没有才退到贡献歌词者（`lyricUser`），翻译链接填该用户主页；
  2. **bilibili 视频评论**链接（带 `comment_root_id=` 或 `#reply…`）→ 翻译者取**评论者**，来源填「**bilibili视频评论区**」（分享的是子评论时优先取那条）；
  3. **bilibili 视频**链接 → 翻译者取**视频投稿者**，翻译链接填其空间主页；
  4. **bilibili 图文 / 笔记**链接（`opus/{id}`）→ 翻译者取**笔记撰写者**（笔记自己的接口需登录态，只能读页面里的作者卡片）；
  5. **巴哈姆特創作大廳**链接（`home.gamer.com.tw/artwork.php?sn=…`，`creationDetail.php` 也认）→ 翻译者取**投稿者**（页面上显示的昵称，没有昵称才用帐号），翻译链接填其小屋，来源填「巴哈姆特」。
  第 2 条判断优先于第 3 条：评论链接里也带 BV 号，会先按「评论」处理。
  只覆盖读到的字段，没识别出来的保留你自己填的内容；失败时会在状态栏说明原因。
- 「完成」返回整理好的歌词（日语与中文不能同时为空），「取消」放弃编辑。
- **鼠标悬停在哪一行，四栏里的同一行会一起高亮**（鼠标所在那一栏颜色更深），校对行对应关系时很好用；鼠标移开即恢复。

### 演唱者上色（`LyricsKai/colors`）

「歌词」页底部勾选「**使用 LyricsKai/colors（演唱者上色）**」，歌词就会改用`{{LyricsKai/colors}}`输出，并按演唱者给歌词上色：

- **颜色**取自 voca.wiki 的[`Module:Vocalist_Colors`](https://voca.wiki/Module:Vocalist_Colors)，**charas**取本曲歌姬（vocadb 的演唱者列表，保持 vocadb 的顺序）；歌姬在颜色表里查不到时用模块的默认色`#333333`。
- 勾上开关后下方会出现「**歌唱者标记**」面板：每行一行，右边一排歌姬按钮（按下时的底色就是该歌姬的颜色），点亮表示「这句是 Ta 唱的」，**一行可以点多个**。
- 面板左上角的「**标记栏**」可以切换 **日语栏 / 中文栏**：两栏的标记与切分点都是**各存各的**，所以中文译文的地方（如译文把两句合成一句、多补了一句）可以单独改，不会连累日语栏；「清空本栏标记」也只清当前那一栏。
- 中文栏不想一行行手点就用「**按日语标记中文**」：
  - 两栏**行数一致**时直接按行号照搬（不联网）；
  - 行数不一致时交给大模型对齐行号（「每行中文对应第几行日语」），再把标记搬过去，搬完自动切到中文栏给你核对——这一步需要`ai_api_key`（与「AI 识别并填入」同一套配置）。
- **行内分段**：一句里几个人各唱一半时（如`@6未来は@1誰も知らない`），把光标放在那一行要切开的位置、点「**切开**」，这一行就分成两段、每段各选各的演唱者；再点「**合并**」就把切口收回去。
  - 日语栏 / 中文栏**各切各的**：两栏都可以单独切分，互不影响；
  - 某一栏没切分过（或译文栏本来就是整句）时，那一栏整行只用第一段的颜色；
  - 空行、`#NoHover`行不写标记；行被改短后超出去的切口会自动丢掉。
- 组合规则（`@n` 标记会同时写进 `original` 与 `translated`）：
  - 只点 1 人 → 直接引用该歌姬的颜色（`@1`…）；
  - 点亮**全部**歌姬 → 记为`合唱(@nolink)`，颜色用交替色`co(色1, 色2…)`；
  - 点 2 人及以上但不满员 → 记为`A+B(@nolink)`，颜色用渐变色`lg(left, 色A, 色B…)`；
  - 一行都不点亮（或某一段没点） → 这一段不写标记，颜色延续上一段；
  - 空行与`#NoHover`行不写标记（`#NoHover`只在悬停模式下出现）。
- 生成参数形如：

  ```
  {{LyricsKai/colors
  |colors= #72A6C0; #EB6238; lg(left, #EB6238, #a1d6b7); co(#72A6C0, #EB6238, …)
  |charas= 宮舞モカ；Ryo；Ryo+花隈千冬(@nolink)；合唱(@nolink)
  |traColors= on
  |charaBlock= on
  |original=
  @1ああ　またダメだったな
  @6未来は@1誰も知らない
  …
  }}
  ```

  `colors`与`charas`一一对应（半角`;`/ 全角`；`分隔），`traColors= on`让译文栏也解析标记，`charaBlock= on`生成角色颜色提示栏。两栏共用同一份`colors`/`charas`——中文栏单独标过时，它的`@n`用的还是这套序号（不会被拆成两份颜色表）。可以和「悬停显示译文」同时开启，模板名会拼成`LyricsKai/colors/hover`（带罗马音时再加`/Roma`）。
- 本曲没有歌姬信息（vocadb 查不到演唱者）时开关会自动失效，仍按普通`LyricsKai`输出。

也可以单独运行`python parse_lyrics.py`，只打开界面里的「歌词」页并打印生成的歌词段落。

## 提交页（实时预览 / 编辑 / 提交条目与封面）

将`config.yaml`中`wiki.submit_window`设为`true`后，程序生成 wikitext 后**不再用 VS Code 打开**输出文件，而是自动切到主窗口的**「提交」页**：

- 左侧可直接编辑生成的 wikitext；
- 右侧实时调用 Vocawiki 的 `action=parse` 接口渲染预览（编辑后自动刷新）：使用皮肤自带文档骨架，自动通过 API 内联 `MediaWiki:Common.css`、`MediaWiki:<皮肤>.css` 等站点 CSS（若 wiki 有配置），并把预览里尚未上传的封面替换为本地已下载的封面图；**在预览里点右键**会弹出中文菜单（返回 / 前进 / 重新载入 / 复制链接地址 / 复制图片 / 检查元素 ……，`lang: en` 时保持英文），菜单项由网页内核按当前点到的位置（链接 / 图片 / 输入框 / 空白处）决定；
- 点击「提交到 Vocawiki」会依次**上传封面 → 创建/更新条目 → 创建重定向**，并把编辑结果同步写回本地 wikitext 文件；
- 所有编辑请求结束后会弹出一个**完成对话框**，逐条列出封面/条目/重定向/模板同步的结果，并可直接点「在浏览器中打开条目」；
- **提交失败时状态栏变红**，并提示「窗口保持打开，可修改后按 `Ctrl+Enter` 重试提交」，改完可以直接再交一次；
- 若同时将`wiki.create_redirect`设为`true`，提交时会额外创建「日文原名 → 中文条目」的重定向（若该页面已存在则不会覆盖）；
- 顶部「同步大家族模板」开关（默认开启）会在条目提交成功后，把这首歌写进`== 注释 ==`里那些模板的对应小节：
  - 达到殿堂（10 万播放）及以上的加入**殿堂曲 / 传说曲 / 神话曲 / 破亿曲目**荣誉小节（同一首歌会同时写进已达成的各档，分站点 / 分年份的子分组会自动定位）；
  - 荣誉小节里**没有这一站的子分组**时（如`Template:可不/2023`的「殿堂曲」只有 niconico / bilibili，而这首歌同时也在 YouTube 上到了殿堂），**只有在整首歌一处都没写进去时**才退到**部分非殿堂曲 / 其他 / 其它**那一组（参《小小星座》：殿堂就是在 YouTube 上到的）——已经写进荣誉小节的话不会再往「其它」里多写一份；
  - 未达殿堂的写进**部分非殿堂曲**小节；模板里没有这一节时（如`{{NurseRobot_TypeT}}`只有「其他」栏）改写到**其他 / 其它**小节；
  - 模板里**完全没有荣誉 / 非殿堂小节**、而是按年份罗列曲目时（如`{{梦的结唱}}`的「優秀曲目 → 2022年 … 2026年」），不管播放量多少都**写进投稿年份那一格**（与 P主模板同一套定位逻辑）；
  - 模板给每条曲子配了色时（`{{coloredlink|#色|页面|{{lj|日文}}}}`，如`{{梦的结唱}}`），新条目的颜色**按本曲歌姬**从模板里现读的配色表取（实测 POPY `#fa006e` / ROSE `#5050d2` / PASTEL `#5bc398` / HALO `#fadc1f` / AVER `#8e2e4a` / MEW `#FF778D`，颜色表不写死在代码里）；歌姬不在表里时**不猜颜色**，写成普通链接。
  - **P主模板**（`{{Chinozo}}`、`{{Dixie Flatline}}`…）写进**投稿年份**那一格（年份标签带不带「年」都认，`{{links|…}}` 与普通列表会照邻居的写法写）；
  - 参加了 The VOCALOID Collection 时，同步 `The VOCALOID Collection20XX季`模板里 **TOP100 / ROOKIE / REMIX** 榜单对应名次的段落（榜外写「未上榜歌曲」）；**多个赛道都在就每处都写 / 都改指**（赛道与名次来自爬那一届的模板，见「使用方法」第 4 条）。写之前会先在整个模板里查一遍这首歌是否已经在别的赛道 / 名次里，已在就不重复添加、只把旧写法改指过去（几处旧写法一次全改）。
  - 模板里若**已经用日文原名链着同一首歌**（条目还没建时的旧写法，如`{{lj|[[どろぼうねこ]]}}`），会把那一条**改指到中文条目**（`{{lj|[[偷腥猫|どろぼうねこ]]}}`），不会重复添加；P主模板的`{{links|…}}`列表同理。**条目名变过也一样**：`{{links|做吧！新鲜的小年轻{{!}}やっちゃえ！フレッシュヤング}}` 里那一项会就地改成 `{{links|做吧! 新鲜的小年轻{{!}}やっちゃえ！フレッシュヤング}}`（显示名与`<!-- -->`注释都不动），不会再排一条重复的。
  勾选后会先显示一份「准备怎么改」的只读说明；结构认不出（没有对应小节、缺名次、模板里没有该年份等）时跳过并在状态栏说明，模板同步失败也不影响条目本身。
- 若将`wiki.disambiguate`设为`true`（默认），提交前会先处理**同名条目**（见下节）：按情况修订 / 创建消歧义页，并把裸标题的链入页面列出来让你确认替换。

提交页是本工具**唯一**的图片上传入口：只有开启`wiki.submit_window`，封面才会随条目一并上传到 Vocawiki。

## 同名条目（消歧义）

把`config.yaml`里的`wiki.disambiguate`设为`true`（默认）后，程序会用**译名**去 Vocawiki 上找同名条目（参考站内条目：[向日葵](https://voca.wiki/向日葵)、[时光机](https://voca.wiki/时光机)）：

- **条目名与封面文件名**改用「**歌名(P主名)**」，例：`向日葵(Teary Planet)`、`时光机(40mP×164)`。P主名直接取 Songbox 里那个名字；是日文时通过 vocadb 取它的**罗马音转写**（`八王子P` → `HachioujiP`、`みきとP` → `MikitoP`）；多个 P主用`×`连接。裸标题没被占用时一切照旧，不加后缀。
- 条目**最顶部**自动加消歧义导航模板（在`{{标题替换}}`与荣誉题头之上）：
  - 同名条目共 **2 个** → `{{About|本条目描述|另一含义|另一条目名}}`；
  - **3 个及以上** → `{{Otheruseslist|本条目描述|描述1|条目1|描述2|条目2}}`；
  - 描述写成「`[[P主]]创作的歌曲`」；同名条目是别的类型页面（如某专辑）时写「同名条目」。
- 提交时：
  - 裸标题**已经是消歧义页** → 往里面补上自己这一行；
  - 裸标题**被另一首歌占用** → 把它**不留重定向**移到「歌名(它自己的P主名)」（从那个条目的 Songbox 里读 P主；是日文时先找**站内指向它的重定向**里的 ASCII 名（实测`雄之助` → `Yunosuke`），没有就查 **VocaDB 的艺术家别名**（`Ar/23981` 的 `additionalNames = Yunosuke, 유노스케`）；两条都没命中才用日文名），再在裸标题上创建消歧义页（里面同时列出两个条目）；
    旧条目的**封面文件**若占着裸标题的名字（`涅槃.jpg`）也跟着改成新名字（`涅槃(Yunosuke).jpg`）并把它的 `|image` 一起改掉（文件还被别的页面用时会给旧名留一个重定向）；
  - 裸标题**被非歌曲页面占用** → 不动它，只把自己的条目名与顶部模板改好。
- 开了 `create_redirect` 时，日文原名重定向指向裸标题（= 消歧义页，站内写法就是`ネハン` → `涅槃`、`ひまわり` → `向日葵`）；裸标题被非歌曲页面占用（不建消歧义页）时仍指向本条目。
- 移动之后，会弹出「**修正链入页面**」列表：链入表（`Special:WhatLinksHere`）里的页面，外加**全文搜索**（`insource:`）找到的模板 / 模块页 —— `{{links}}` 那类链接是 Lua 现拼出来的，根本不进链入表（实测`Template:雄之助`就不在`涅槃`的链入表里），只搜出来还不够，还要能真改的才列进去。逐页显示能替换几处、改的是哪种写法，并给出上下文，勾选后点「替换选中页面的链接」就会把引用改到新条目名。支持这几种写法：
  - **wiki 链接**：`[[旧条目名]]`、`[[旧条目名|显示文字]]` —— **只换链接目标，显示名保持原样**：`[[涅槃]]` 改成 `[[涅槃(Yunosuke)|涅槃]]`（不是 `[[涅槃(Yunosuke)]]`；
  - **模板参数**：榜单类页面（《周刊VOCALOID排行榜》《周刊VOCAL Character & UTAU排行榜》等）并不写 `[[ ]]`，而是用模板 `Template:VOCALOID & UTAU Ranking/bricks` 的参数拼出链接目标（`[[{{{条目|{{{曲名}}}{{{后缀}}}}}}|查看条目]]`），所以这里会改 `|条目 = 旧条目名`，或在只有 `|曲名 = 旧条目名` 时补一行 `|条目 = 新条目名`、在 `曲名 + 后缀` 拼出旧名时改写`后缀`（都保留表格里显示的歌名）；
  - **位置参数（曲目列表）**：P主模板 / 榜单模板用 `{{lj|{{links|条目名{{!}}日文名<!--…-->}}}}` 罗列曲目（`{{links}}` 把每项渲染成 `[[条目名|日文名]]`），这里只改 `{{!}}` **左边**的条目名：`涅槃{{!}}ネハン` → `涅槃(Yunosuke){{!}}ネハン`（日文显示名与注释都不动）。
  已经是新名的链接、模板参数、纯文字都不会动；实在认不出的页面会标灰并说明「可能通过模板 / 模块链入」。
- 移动与建页都有进度标记：某一步失败后再点一次提交**不会重复移动**，只会继续没做完的那一步。
- 没有 P主名可用时（vocadb 查不到 P主）无法生成后缀，程序会在日志与提交页里提醒你手动处理；旧条目那边没写 P主 时同样无法给它改名让出裸标题，这时只用自己的带后缀条目名、不建消歧义页。

以上探测与修改都需要登录 Vocawiki（`wiki_credentials.yaml` 里的账号需要有**移动页面**权限）。

```yaml
wiki: !WikiConfig
  submit_window: true
  create_redirect: true
```

### 账号配置

在`wiki_credentials.yaml`中填写你的 Vocawiki 账号信息。出于安全考虑，建议使用**机器人密码**而非主账户密码：

1. 登录 Vocawiki，打开「参数设置 → 机器人密码」（或访问`Special:BotPasswords`）。
2. 创建一个机器人密码，授权至少勾选「上传新文件」「编辑现有页面」等权限。
3. 在`wiki_credentials.yaml`中填写：
   - `username`：`你的账户名@机器人名`（例如`TimeRen@tool`）
   - `password`：机器人密码（不是主账户密码）

```yaml
# wiki_credentials.yaml
username: "你的账户名@机器人名"
password: "机器人密码"
```

未登录时仍可预览与编辑，只是无法提交。若已下载封面，程序会在提交前询问封面中出现的歌姬，用于生成文件说明页的分类。

如果出现无法解决的问题，程序会
1. 询问用户该怎么办。例如：在vocadb上找到多个同名歌时让用户做决定；找不到歌曲的中文翻译时要求用户提供。
2. 崩溃。遇到这种情况请联系作者修复bug。

## 自己构建（打包 exe）

Windows 上双击 **`build.bat`** 就能打包，它会先把环境准备好再调 `build.py`：

1. **找 Python**：优先用项目自带的 `.venv\Scripts\python.exe`；没有 `.venv` 就用系统的 `python`（或 `py -3`）建一个；
2. **检查依赖**：PyInstaller / PyQt5 / yaml / requests / PIL / numpy 缺哪个就 `pip install -r requirements.txt`；
3. **打包**：只在项目根目录生成发布包 `Vocawiki-create-tool (版本号).zip`（exe + 运行时资源，解压即用）。项目里**不会**留下 `dist\` ：exe 先放在临时目录里，打完包连同中间产物一起删掉（打包失败时会保留 `build\` 方便看 `warn-*.txt`）。

```bat
build.bat 1.3.1      :: 直接打包 1.3.1
build.bat            :: 不带版本号，build.py 会问一次（回车用 0.0.0）
build.bat --check    :: 只检查 Python 与依赖，不打包
```

- 双击运行结束时窗口会停下等你按键；从终端里调用则直接返回（退出码 0 = 成功）。
- `build.bat` 自己的提示是英文的（免得撞上非 UTF-8 控制台变成乱码），`build.py` / PyInstaller 的输出照旧。

Linux / macOS 上走的是同一个 `build.py`：

```bash
make build VERSION=1.3.1     # 或 make build（会问版本号）—— 同样只在根目录留 zip
make source                  # 源码包（不含 exe，顶层目录是 Vocawiki-create-tool (版本号)/）
./make_source.sh 1.3.1       # 同上，只是不开头走 make
python build.py --source     # 源码包的底层命令；`python build.py --help` 没用，看 build.py 开头注释
```

两个包里的 `wiki_credentials.yaml` 都是**清空过密钥的模板**（账号、密码、AI key 一律写 `""`）。
- 不想用脚本也可以手动：`python build.py 1.3.1`（前提是依赖已装好）。
