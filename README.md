# Vocawiki-create-tool Vocawiki条目辅助工具

Automatically generates Wikitext for Japanese VOCALOID songs, tailored specifically for the [Vocawiki](https://voca.wiki/). If you are not a Chinese speaker, this project is probably useless to you.

本程序用于生成自动[Vocawiki](https://voca.wiki/)的日语VOCALOID歌曲条目。本仓库主体代码来自于[MGP-VJ-tool](https://github.com/lihaohong6/MGP-VJ-tool)，并在此基础上修正了一些bug并添加新功能。

## 启动方法

从[releases](https://www.github.com/TimeRen/Vocawiki-create-tool/releases) 下载、解压后运行 `Vocawiki-create-tool`。

左侧竖栏：

- **功能**：选「生成歌曲条目」「生成P主模板」「生成歌姬模板」；切功能会把当前这一轮停掉、界面复位。
- **头像**：点一下登录 Vocawiki（再点可重新登录 / 退出登录 / 改账号密钥）。
- **齿轮**：打开「设置」页。

右侧标签页（「样式」「歌词」「曲目」「提交」平时是灰的，流程走到那一步自动点亮并切过去）：

| 标签页 | 做什么 |
| --- | --- |
| **填写信息** | 按提示在下方输入（输入框 / 整段粘贴 / 选项按钮）；「清空」只清当前输入（Ctrl+L），「确定 / 完成」提交 |
| **日志** | 看网络请求、上传进度、错误与 `print` 输出 |
| **样式** | 调歌曲配色或模板配色 |
| **歌词** | 整理歌词 |
| **曲目** | 改曲目 / 专辑清单 |
| **提交** | 预览 / 编辑 / 提交到 Vocawiki |
| **设置** | 点齿轮才出现，保存成功或切走自动收回 |

底部状态栏显示当前走到哪一步；窗口拖窄时当前页会自己出滚动条。

纯终端用法：`Vocawiki-create-tool --console`；模板两条流程是 `--console --producer`（P主模板）与 `--console --vocalist`（歌姬模板）。

## 生成歌曲条目（侧栏第一个功能）

1. 侧栏「**功能**」选「生成歌曲条目」。
2. 「填写信息」页依次回答：**日语曲名**（必填）→ **中文曲名**（与日语相同或没有翻译就留空）。**在 VocaDB 上搜歌名时会认全角 / 半角**（`５℃` 与 `5℃` 视为同名）、忽略大小写与空白，并且只搜 `Original`：实测《[5℃](https://voca.wiki/5℃)》的原创曲在 VocaDB 上是**全角**的「５℃」（おかゆ / GUMI / sm22630254 / 2014-01-10），半角「5℃」是一条**翻唱**（UTAU，视频已删）—— 按字符串严格相等时原创那条会被过滤掉、只剩翻唱，整条条目（歌姬 / P主 / 投稿日 / sm 号）都会写错。**歌名对应好几首时每次都会让你选**（选项写成「歌名 by 歌手（投稿日期）」，VocaDB 上《パンドラ》同名的原创曲就有 17 首）；这种「同名不同曲」的歌名**不会**记进 `output/vocadb_cache.json` 的「歌名 → id」缓存 —— 以前会记，结果再生成另一首同名曲时直接拿上一首的资料（P主 / 歌姬 / 投稿日 / 封面全是错的），重启也改不回来（用户 2026-10-25 报）；只有「名字只对到一首歌」时才缓存（同一个条目再生成一次不发请求）。老版本留下的那份「歌名 → id」升级后第一次启动就作废（缓存文件带版本号）；开着 `vocadb_manual`（每首都要你确认）时干脆不认这条缓存。B 站稿件优先用 **VocaDB 自己记着的那条**（VocaDB 里搬运件就标成 `Reprint`，官方投稿是 `Original`；实测《- メランコリー -》的搬运件 `av805954445` 在 b 站搜索里根本搜不到，只有 VocaDB 记着它）；VocaDB 没记时才按曲名去搜：标题 / 简介里明确写着「搬运 / 转载 / 补档」的直接按非官方投稿处理；UP 主与 P主 对得上就按官方投稿处理；拿不准（或搜到多个同样可信的候选）才弹窗让你选 / 确认，**选「都不是（手动输入链接）」后可以直接把 b 站链接贴进来**（留空则这一趟不要 B 站稿件）。搜索会同时试「P主 + 歌名」「歌姬 + 歌名」，以及**只搜 P主 名**（b 站把多关键词拆得很碎，「0.5秒 謝謝P」这种组合反而搜不到；单搜「謝謝P」时他的稿件排在最前面，再按歌名过滤 —— 用户 2026-10-24 报的《0.5秒》就是这样才搜到 `BV1uW411x7g9`），并把 Remix / Arrange / two-step mix / Live 版等**同曲异版本**降权，优先选原投稿。完全没搜到时也退回手填链接（支持 `b23.tv` / `bili2233.cn` 短链，`?vd_source=…` 这类分享参数会被忽略；指向图文而不是视频时会让你重填）。
3. 参加了 The VOCALOID Collection 时不用填赛道与名次（程序自己读那一届的活动模板）；读不到才问，那时选 TOP100 / TOP30 / ROOKIE / REMIX / 榜外。
   - **投稿日期的取法**：优先用站点自己报的（niconico 的 `uploadDate` / nicolog 的最后记录 / b 站 API / YouTube 元数据）；站点取不到（稿件已删除 / 非公開，或被 Cloudflare 挡了一下）时用 **VocaDB 记在「这一支稿件」上的 `publishDate`**，只有稿件自己没记才退回**歌曲级**的 `publishDate`。以前一律退回歌曲级日期，于是已删稿件会把投稿日写成歌曲那条记录上的旧值 —— 实测《[荒唐之事](https://voca.wiki/荒唐之事)》的 nico 稿件 sm41195996 是 `HIDDEN_VIDEO`（2022-10-08 投稿），VocaDB 的歌曲级 `publishDate` 却是 `2020-11-15`，条目因此写成了「2020年11月15日投稿至niconico」，站上改成 2022-10-08（用户 2026-10-27 对照 diff 275978 → 276140）。
4. 「样式」页调 Songbox / Introduction / 歌词 三段颜色（自动载入封面、可用吸管取色，每项都能单独「输出」或关掉）。
5. 输完曲名就会切到「歌词」页整理歌词（见「歌词页」）：日语原文已经预填在「日语」栏，补上译文就行。
6. 「提交」页实时预览、手改，点「**提交到 Vocawiki**」：上传封面 → 创建/更新条目 → 创建重定向；失败时状态栏变红，改完按 `Ctrl+Enter` 重试。

流程跑完不再弹「生成流程已结束」的居中窗口，而是直接停在「提交」页；没开 `wiki.submit_window`（提交页没被点亮）时仍走原来的老路：用 VS Code 打开输出文件。

要用到的开关（改 `config.yaml`，或点齿轮在设置页里勾）：

| 开关 | 打开后 |
| --- | --- |
| `wikitext.uploader_note` | 询问投稿文（多行输入，空行结束） |
| `wikitext.human_original` | 多问一句「是否存在人声本家」（同一首歌的人声演唱版本）；回答「是」再依次要 niconico / YouTube 链接与 bilibili 链接，都可留空跳过 |
| `wikitext.other_versions`（默认开） | 从 VocaDB 列出同一首歌的翻唱 / 改编版本让你挑，再问该版本的 bilibili 链接与「B 站投稿是P主自己提交的吗」；挑中的版本会**另外取一次它自己的详情**（演唱者、nico / YouTube 稿件、专辑），见下 |
| `wikitext.lyrics_chs_fail_fast` | 不弹歌词页：让工具自己去 AtWiki 找中文歌词，找不到就留空（默认关，即输完曲名就弹歌词页） |
| `wikitext.furigana_all` | 给歌词里没写读音的汉字标 `{{photrans|汉字|假名}}`（用 AI） |
| `image.download_cover` | 下载封面并随条目上传 |
| `image.crop`（默认开） | 裁封面黑边 |
| `wiki.submit_window` | 生成后切到「提交」页，而不是用 VS Code 打开输出文件 |
| `wiki.disambiguate`（默认开） | 处理同名条目（见下） |
| `wiki.create_redirect` | 额外创建「日文原名 → 中文条目」的重定向 |
| `wiki.edits_per_minute`（默认 3） | 提交编辑的频率上限（平均每 `60 / N` 秒一次，`0` = 不限制） |
| `vocalist_vocadb_catalog`（默认 6000） | 歌姬模板：拿殿堂 / 传说页上的 PV 编号去 VocaDB 核对该歌姬曲库时**最多翻多少首**（`0` = 关掉这一步），见「生成歌姬模板」 |

⚠️ 关掉 `wiki.submit_window` 封面就不会上传（提交页是本工具**唯一**的图片上传入口）。

### 其他版本（`wikitext.other_versions`）

挑中一个版本之后，工具会**另外取一次它自己的 VocaDB 详情**，把那一版的演唱者、nico / YouTube 稿件、收录专辑都读回来：

- `|演唱` 与简介里的「由…演唱」用的是**这一版**的歌姬。VocaDB 的候选列表（`alternateVersions`）只写 `artistString`，很多歌写着 `feat. various`；真实名单只在详情里的 `artists`（例：《13943号室》的 Live 版是 KAITO / 神威乐步 / 镜音连，比原版少一位冰山清辉）。
- 版本名照旧是 `歌姬版`；**歌姬认不出来时**改用版本自己名字里的说明 —— `＋＋＋▶▶▶13943号室 (2018 LiveVer.)` → tab 与封面文件名都是 `Live版`（`13943号室(Live版).jpg`），`ROCK_VER` → `ROCK版`。
- B 站那份是**转载**（你回答「不是 P主 自己提交的」）时，`|bb_id` / `|bb_date` **不写**，只用 `{{BilibiliVideo}}` 当播放器（与主版本 Songbox 同一套规矩）。
- **同一首歌、同一位 P主 的另一次投稿**（Live 版 / 重录，VocaDB 常写成 `Mashup`）简介里算「日语**原创**歌曲」，不是「翻唱」；专辑那句的主语也换成「**此版本为2018 Live版**，收录于专辑《…》」（参 voca.wiki《13943号室》diff 275394）。VocaDB 明说是 `Cover` / `Remix` / `Arrangement` 的仍按翻唱 / 改编写。
- 那一版自己的投稿年也算进注释区的歌姬模板：Live 版 2018 年投稿，《13943号室》末尾因此同时有 `{{KAITO/2012}}` 与 `{{KAITO/2018}}`。
- 自动搜 b 站稿件时，标题里带 `Live` / `ライブ` / `演唱会` 的**不算本曲的原投稿**（用户 2026-10-23：《13943号室》曾被搜到 Live 版那条、写进了主 Songbox 的 `|bb_id`）。歌名自己带这个词（如《Live Forever》）时不会误判。

歌名 / P主 / 专辑名外面的 `{{lj}}` 只套在**真有日文**的名字上：`{{lj|13943号室}}`（汉字）、`{{lj|鳥の詩}}`（假名）、`{{lj|VanaN’Ice …}}`（弯引号）照旧；`-２５-` 这种只有全角数字与连字符的**不套**（全角按半角算之后一个日文字都没有 —— 参 voca.wiki《-２５-》diff 275395）。

### 连不上 VocaDB（超时 / 打不开）

VocaDB 取不到数据时工具**不会**把 `requests` 那一串 `Max retries exceeded … (connect timeout=30)` 原样甩给你，而是：

1. **连不上**（DNS / 连接超时 / 代理没开）先按 2 秒、5 秒的间隔重试两次，再借本机浏览器取一次 —— 浏览器走的是**系统**代理，常见的情况就是「浏览器能打开 vocadb.net、工具却超时」；
2. 还不行才报一句「连不上 VocaDB」（附原始错误），并提示检查网络 / `config.yaml` 的 `proxies`（如 `http://127.0.0.1:7890`；只有配了 `proxies` 的请求才走代理）；此后 **2 分钟**内不再硬试（否则每个歌名都要白等几次超时），这期间仍然会试浏览器，改了 `proxies` 就立刻恢复；
3. **被 Cloudflare 挡住**（403 挑战页）走的是另一条路：借浏览器 → `vocadb_cookie` / `vocadb_user_agent` → 手动粘 JSON，详细步骤写在程序日志里那段说明中；只是取歌词时失败的话会自动改用 AtWiki 的日文歌词，不会把整首歌作废。

### 同名条目（`wiki.disambiguate`）

开着时程序全自动处理（条目名与封面文件名改成「歌名(P主名)」、顶部加消歧义模板、把占用裸标题的那首歌移到它自己的后缀下、**给那首歌补上 `{{标题格式化}}` 与指向本条目的 `{{About}}`**、在裸标题上建消歧义页）。你要做的只有：

1. 移动后弹出的「**修正链入页面**」窗里勾选要改的页面；
2. 点「**替换选中页面的链接**」。

括号里的 P主名按**站上的写法**来（用户 2026-10-15）：名字在站上是重定向就用真条目名（`|P主 = [[livetune|kz(livetune)]]` 那首歌 → `Redial(kz)`），日文汉字过一遍站点自己的变体转换写成中文汉字（`鶴三` → `Redial(鹤三)`、`稲葉曇` → `稻叶昙`、`積木P` → `积木P`），假名写罗马音（`柊キライ` → `柊kirai`、`蜂屋ななし` → `蜂屋nanashi`），结尾的 `P` 照写（`八王子P` 不变）。

被让出裸标题的那首歌改成 `歌名(P主名)` 后，条目顶部会补上 `{{标题格式化}}`（把标题里的括号后缀去掉再显示；它自己已经写了 `{{标题替换}}` 就不动）与指向本条目的 `{{About}}`（参 voca.wiki《Redial(kz)》）；本条目自己的标题也用 `{{标题格式化}}`（中译名与日文原名同形时）或 `{{标题替换|日文原名}}`，所以两条目名的括号后缀都不会显示在标题上。

裸标题上已经有消歧义页时，除了把本条目加进去，还会**检查页面上已有的各条目**：缺 `{{About}}` / 标题模板就补上（同名条目 ≥ 3 个时写 `{{Otheruseslist}}`；页面自己已经写了消歧义模板的不动；读不出 P主 的 —— 软件 / 专辑 / 人物页面 —— 跳过）。每一步都会写在提交结果里。

消歧义页的列表要**把站上所有同名曲都列上**（用户 2026-10-25 对照《[潘多拉](https://voca.wiki/潘多拉)》diff 275790 → 275795）：除了「本条目」与「让出裸标题的那一首」，还会按**日文原名**全文搜一遍条目命名空间（`insource:"パンドラ"`），再用 Songbox 的 `|歌曲名称=` 精确核对（全角 / 半角、空白都算同名），命中的补进列表 —— 实测《パンドラ》因此补上了 `[[Pandora]]`（ATOLS 制作，ATOLS 那首的条目名是英文，光看译名「潘多拉」根本找不到它）。这些「别的同名曲」**只进消歧义页的列表**，不动它们自己的正文（站上 Pandora 那一页只有 `{{标题替换}}`，没有 `{{About}}`）。另外那一行里的歌姬也改用**站上的中文条目名**（`[[初音ミク]]` → `[[初音未来]]`，与 Songbox 的 `|演唱=` 同一套写法）。

账号需要有**移动页面**权限。

**同一首歌在两处都同名时**（用户 2026-10-28 给的《[EDEN(醉shigure)](https://voca.wiki/EDEN(醉shigure))》两笔差异）：活动模板「同步大家族模板」与「赛道 / 名次」识别都会**判链接归属**，不再只按歌名匹配 —— `歌名(我们的P主)` 与完整条目名优先，裸链接 `[[EDEN]]` 只在同一赛道里还没有「我们的」条目时才算数（一首歌在一个榜里只有一个名次）。所以 2022春 那一届两首《EDEN》时：本曲认 `[[EDEN(酔シグレ)|ENDN]]`（TOP100 第 66 名 + ROOKIE 第 39 名），另一首的 `[[EDEN]]`（第 97 名）既不会被当成本曲的名次，也不会被改指成 `EDEN(醉shigure)`；反过来，本曲只写成日文 P主名的那一处照样会改指到 `EDEN(醉shigure)`（显示名原样保留）。

## 样式页

- 左上封面图下面的「**导入图片**」挑的那张图既当参考图（吸管取色 / AI 配色），**也是提交时上传的封面**：导入时**当场**把非 JPG 的图（png / webp / gif）转成 JPG（透明的地方铺白底），之后预览、AI 取色 / 超分都用这份 JPG；保存时它被复制成 `output/<译名>封面.jpg`（提交页上传的就是这个文件），不再用自动下载的那张；点「**移除图片**」就退回自动下载的那张。只是导入来取色、最后没点「保存并继续」的话，输出目录里的封面什么都不会动（导入时转出来的 `*.import.jpg` 也会删掉）。封面不裁剪、不缩放，导入的是哪张提交的就是哪张（站上文件名仍是 Songbox 里的 `<条目名>.jpg`）。提交时会覆盖站上的同名旧封面（`ignorewarnings`），所以给已有条目换图不必先手动删文件；超过 800 万像素 / 12 MB 的图会先缩到站点更稳妥的尺寸再传。
- 旁边的「**取该版封面**」按**当前选中的版本**（主版本 / 某个其他版本）在各站的稿件重新取一张封面，直接写成那一版的封面文件（其他版本以前只能自己截图再导入）；这一版已经有封面时会先问一句。
- 封面太糊时点「**AI 提升封面分辨率**」：把当前封面交给 waifu2x 公开接口提升分辨率并降噪（免费、不需要 `ai_api_key`），结果显示回封面区，并同样作为提交封面；点「保存并继续」后才写进提交文件。原图不会被改动。小封面（最长边 ≤ 800）输出 4 倍，预览缩放后才不发虚；大图输出 2 倍。在线接口被墙 / 返回错误页时会自动下载约 5 MB 的本地 waifu2x CUnet 模型（waifu2x-caffe / MIT 的 ONNX 转换，首次使用需联网）继续做 AI 超分；只有本地模型也不可用时才退回 Lanczos + 锐化，并在按钮下方说明原因。
- 左边两个文本框可以直接手写，**切标签、改右边控件都不会覆盖**：`Wikitext 参数`（三块颜色 + 模板参数）点「**从文本载入**」解析回模型，`完整 CSS（可编辑）` 点「**应用代码**」应用进模型。只有点「重置当前 / 重置全部」「用 AI 生成」或开始新一轮生成才会重新生成。
- 左边的预览照站上的真实结构画：Songbox 三块竖排居中、Introduction 标签格 + 列表、歌词**一行 = 原文 + 译文并排**（各占 49.85%，文字左对齐 —— 桌面端 `body.main-sm` 的实测结果）；封面图与这三块共用同一条中线，方便对着封面调色。「显示范围」只画其中一段，`画布宽` / `间距` 调预览尺寸。**同一位置的两个色标（CSS 的硬切换）也照 CSS 画**：`linear-gradient(135deg, #02013d 60%, #d7dee6 60%)` 在站上是「深蓝铺到 60%，之后立刻变浅灰」，预览以前把整块画成浅灰（白字直接看不见）—— Qt 的 `setColorAt()` 以位置为键，同位置的色标会**覆盖前一个**，只剩最后一个颜色；现在同位置的色标之间让出 0.05% 的间距（一个像素都不到的硬边），两种颜色都在（用户 2026-10-28 报）。
- 预览与 `|颜色1` 上的 `background` 走同一套解析，照着 [[User:JackBlock/CSS background]] / [[User:JackBlock/渐变色使用]] 两个页面的例子逐条对过（Chromium 渲染 ↔ 预览渲染逐像素比对）：线性 / 径向 / 锥形三种渐变、`repeating-*`、`to top right` 这类角方向（按盒子宽高算渐变线，200×100 里是 26.57° 而不是 45°）、径向的 `circle` / `ellipse` / `closest-side` / `closest-corner` / `farthest-corner`（椭圆保持盒子宽高比）、锥形的 `from … at …`、色标的位置单位（`px` / `%` / `deg` / `rad` / `turn` / `grad`）、颜色提示（`#FF7777,20%,#7777FF` 里的 20%）、一个节点两个位置，以及背景块自己的 `position / size / repeat / origin / clip`（`0 0/20px 20px repeat-x`、`content-box`、`text` 都认）。写回 wikitext 时保留原来的单位与尾巴，不会把 `radial-gradient(a,b,c)` 改写成带 `60% 40%` 的另一条渐变（用户 2026-10-30 报）。
- 右侧「**辅助工具（测量 / 参照物）**」只是屏幕上的尺子，不写进 wikitext：点「开始测量」后在预览台或封面图上点两下量距离；选好线段 / 矩形与角度、宽高后点「开始放置」再在画布上点一下放一个。`Esc` 或右键退出工具模式，与取色吸管互斥。
- 歌词三项（容器 `containerstyle` / 原文 `lstyle` / 译文 `rstyle`）默认不写进 wikitext（`{{LyricsKai}}` 不带它们也照常显示）；**改过这一项的样式就会自动把「在 Wikitext 里输出该参数」打开**（不想要了把勾去掉）。底色要在色盘里挑过才会写 `background`：原文 / 译文默认是「透明」的占位值，挑颜色时透明度会自动变成 100%；点「透」是明确的透明 —— 那样不再写 `background`。**原文 / 译文没自己设文字样式时会继承容器**（站上 `.Lyrics-original` / `.Lyrics-translated` 的 CSS 只写了 width / display / white-space，`lstyle` / `rstyle` 不写就跟着 `.Lyrics` 的 `containerstyle` 走 —— 颜色、字号、字重、字距、文字阴影都算）：所以只改「容器」的文字颜色就能整段换色，预览也照这个样子显示（以前预览各画各的，容器设成白字还是黑字，用户 2026-10-22 报）。
- 「AI 参考封面生成 CSS」按钮见「AI 配色与密钥」。

## 程序更新（不用再重新封装）

设置页最下面的「**程序更新**」直接从 GitHub 装新版（exe 与 APK 都有），改完代码推上去等 CI 发版就行：

1. 点「**检查更新**」（手机上点一下就走完全程：查版本 → 直接下载 → 弹出系统安装界面）→ 问 `TimeRen/Vocawiki-create-tool` 那个「最新构建」release（CI 只维护这一个，每次推送覆盖里面的文件），底部显示「发现新版本 1.27（当前 1.0）」这类说明。
2. 点「**下载并安装**」：下载期间**窗口右下角有一个进度环**（显示百分比；不知道总量时转圈），设置页那一行也跟着显示进度；下载断了会提示「下次会接着下」，**再点一次就是断点续传**（桌面版下到 `%TEMP%/vocawiki-update/`，手机版下到应用目录的 `update/`，都用 HTTP `Range` 从断点继续，不用从 0 重下 140 MB —— 用户 2026-10-24 要求）。
   - **exe**：下载 zip、解压、只替换 `Vocawiki-create-tool.exe` 与 `i18n/`，然后自动重启。`config.yaml` / `wiki_credentials.yaml` **不会被覆盖**（更新包里虽然有模板，但会跳过）。exe 正被占用时会写一个批处理，等程序退出后再替换（提示「几秒后会自动重新打开」）。重启新进程时会带上 `PYINSTALLER_RESET_ENVIRONMENT=1`，让它重新解压自己的临时目录 —— 否则新进程会复用旧进程的 `_MEI…` 目录：旧进程退出时删不掉（弹「Failed to remove temporary directory」），新进程还会因为目录被删而**登录 Vocawiki 失败**，必须再重启一次。
   - **APK**：下载完直接把 APK 交给系统安装器 —— 屏幕上就是「是否安装」那一屏（先写进系统「下载」目录拿到 `content://` 再 `ACTION_VIEW`，Android 10+ 走 `MediaStore.Downloads`，8/9 退回 `MediaStore.Files`）。没开「允许从此来源安装应用」时会**直接跳到那个开关**，打开后回来再点一次即可。全程不把文件字节交给 Python 的 `bytes`（见下），也不用先存到文件再让用户自己去点。
3. 没有发过版 / 网络不通时只会给一句说明，「打开发布页」始终可用。

所有 APK 都用仓库里那份固定的 debug 钥匙（`mobile/signing/vocawiki-debug.keystore`）签名：AGP 在没有 `~/.android/debug.keystore` 时会**当场随机生成**一把，于是 CI 每次发版都是新签名，手机上的旧版根本装不上（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`，用户 2026-10-21 报的「签名冲突」）。`build_android.sh` 构建完会用 `apksigner` 拿仓库那份钥匙重新签一遍，本地与 CI 因此共用一把钥匙；CI 还会核对新 APK 的签名指纹。**从这个版本开始换成了固定钥匙**：手机上一次装的是旧钥匙签的包时，先卸载一次再装，之后就都能原地升级了。

当前版本号来自打包时写进程序的 `_build_info.py`（`build.py` / `build_android.sh` 生成，源码运行显示「未标注版本」）。CI 的版本号见下面「自动发版」一节（取现存最高版本、补丁位换成工作流序号，例如 `2.4.36`），手动触发时可以在输入框里指定。

## 歌词页（整理歌词）

输完日语 / 中文曲名后**直接切到「歌词」页**（日语原文已经预填在**「日语」栏**；本曲歌姬也会一起带过来）。想跳过这一步就设 `wikitext.lyrics_chs_fail_fast`：那时不开歌词页，工具自己去 AtWiki 找中文歌词，找不到就留空。

1. 「日语」栏里已经是原文；中文译文可以手打，也可以照第 5 步从链接拉。整段混排的歌词（日语 / 中文 / 罗马音）粘到左边「待归类歌词」栏也一样。
2. 点「**自动识别并填入**」按语言分栏；都认不出来时它会给一套「每组行数 + 各语言行号」，再点「**按行号转换**」切分。
3. 排版很乱（带编号 / 时间轴 / 混排）时点右上角「**AI 识别并填入**」交给大模型分栏（只分栏，不翻译不改写；开关是 `wikitext.ai_lyrics`）。**来源本来就是「一行日文、一行中文」（「从链接填充」取网易云时就是这样）时不用模型**：直接按位置分栏，100% 对得上、也不用等（这种形状里**整行英文**也算日语栏那一格 —— 一首大半是英文的歌，37 句里 24 句英文，以前因为「带假名的行不到一半」被当成认不出、整段丢给模型，用户 2026-10-27 对照《[binary biotope](https://voca.wiki/binary_biotope)》报的）；日语栏已经有原文（VocaDB 给的是合并行）时，译文会按日语栏的换行**合并**成同结构（中间留一个空格，一个字都不改）—— 实测网易云《パンドラ》50 句逐句译文 + VocaDB 30 行合并原文，一键得到 30/30 一一对应。**这种「逐行配对」只说明谁配谁，段落边界（`#NoHover`）在纯文本里根本看不出来**（网易云的时间戳也判不出来：真正的段落间隔 5.0～5.3 秒，同一段内部也是 5.2～5.3 秒），所以整首一个空行都没有时会**多问模型一次「在第几行之后空一行」**（只收一个行号数组，行数 / 行序 / 每个字都必须原样；AI 关掉、没配密钥或答不上来就照原样不分段返回）。交给模型之前，日语里的「漢字(かんじ)」会先转成 `{{photrans|漢字|かんじ}}` —— 模型看到括号注音时常把读音当成可删的注释，返回「矜持きょうじ」这种糊进正文的写法（实测《欢。》）；转成模板后它只会原样抄回来。**「待归类歌词」是空的**、日语栏与中文栏都已填好时，这个按钮改做另一件事：按日语栏的行数 / 分段给中文栏排版（同样只动换行，模型改了字会拒收；模型只断行、没留段落空行时，工具会按日语栏补回去）。来源是「日语一整块 + 中文一整块」（两侧各占一段）时，中文会先按行与日语对折再配对，不会再整块堆在日语后面或与日语栏错位。来源**只有中文、译者自己用空行分块**时（b 站评论区最常见），先按日语栏的分段把译者的换行合并回去 —— 每块要么合并成一行（合并处留一个空格）、要么原样保留，各段宽度必须正好等于日语栏那几段的行数，且**分法唯一**才动手，一个字都不改（实测《[幽灵(KAIRUI)](https://voca.wiki/幽灵(KAIRUI))》的 b 站评论：17 行 / 5 块 → 条目里的 11 行 / 3 段，三次点「AI 识别并填入」都不用花请求；分法不唯一就照旧交给模型）。模型那条路上，提示词现在两个方向都写明了：译者把一句拆成好几行短句时要**合并成一行**（只在合并处留一个空格），一句译文覆盖两行日语时整句留在第一行；模型要是「一个换行都没合并」就原样交回来（中文比日语多、排版后行数却没变），工具会**判这次失败**让你重试，而不是把「行数对不上 / 看着对得上其实全错」的结果填进去。
4. 四栏都可手改；鼠标悬停某一行时，四栏里的同一行会一起高亮。三个模板开关就在「**AI 识别并填入**」那一行：**使用 LyricsKai/hover** 让译文只在悬停时显示（与罗马音互斥）、**使用 LyricsKai/colors** 走演唱者上色（见下）、**使用 LyricsKai/Roma** 勾了才出现「罗马音」栏（栏里的内容也只有勾着才会写成 `|photrans=`；AI 分出的罗马音在没勾时会提示一句）。
5. 填好「**来源链接**」后点「**从链接填充**」：自动补翻译者 / 翻译链接 / 来源，**并把歌词一起填上**（只覆盖读到的字段，失败会在状态栏说明）；**只有中文**的歌词（不少 AtWiki 页面只写译文）直接进「中文」栏，中日混杂的进「待归类歌词」栏等着分栏。**打开歌词页时会先自己去 vocaloid中文歌词wiki 查一次**：站上有这首的翻译，就把链接与「从链接填充」会填的东西（译文、翻译者、来源）预先填好，省得再点一次按钮（AtWiki 对普通请求一律回 Cloudflare 挑战页：能走系统自带的 `curl` 就先走它，只有它也拿不到时才借你的浏览器 —— 那个窗口开在屏幕外，看不见也不会抢焦点；取不到内容时只填链接）。**同名的歌在站上有好几首，预填前会核对页面里嵌的稿件编号**（`sm…` / `BV…` / YouTube id）是不是本曲那一支：实测《[潘多拉](https://voca.wiki/潘多拉)》（buzzG 的《パンドラ》/ `sm39484089`）会命中**やしきん** 那首同名《パンドラ》（`sm10349470`）的翻译页 —— 两页标题都只写「パンドラ」，但稿件编号不同；核对不上就什么都不填（连链接也不填，免得「从链接填充」又拿回别人的译文）。填 b 站**评论**链接时，除了那条评论本身，**它下面的回答**里像歌词的部分（译者常把后半首写在自己的回复里）也会一起填进来。来源里的**杂物行**会被自动摘掉：`作詞：…` / `作曲：…` / `編曲：…` / `歌：…`、`曲　動画：…`、`Lyrics: …` 这类署名行，`曲/KAIRUI` / `译/千歲世野` 这种**用斜杠代替冒号**的写法（真机 b 站评论《幽灵(KAIRUI)》的头两行，以前会跟着译文进中文栏）、`sm…` / av… 视频号、整行链接、`20` 这种纯数字行、`-----` 分隔线、`www`、`Sheena版:` 版本标签、AtWiki 正文开头那行歌名（`-273.15` 与正文里的 `273.15` 算同一首）、`（動画より書き起こし）` 这种「歌词是听写下来的」来源说明，以及译者 / 转载者的**自述**（`歌词渣翻。大部分机翻+个人理解。如有错误，欢迎指正`、`轉載請註明出處`、`基於相互尊重，請取用翻譯者不要改動我的翻譯，感謝`）、AtWiki 页尾的 `tag：P名,曲名,…` 标签行；AtWiki 页面里 `<hr>` 分割线**之后**整段都是译注（`東北地方太平洋沖地震應援曲。` 这种说明）也不再当歌词；b 站评论里 `【歌词】` / `[歌詞]` 这种**栏目标签**连同**标签之前那句说明**（`这是一个关于时钟的短针爱上长针的故事` + `【歌词】`，真机《Short Hand》）一起摘掉。**译者名后面的括号是自述、不是名字**：AtWiki《パンドラ》的表头写着 `翻譯：cyataku(不當之處敬請指正)`，工具只取 `cyataku`（括号里像「一句话」才去掉 —— 含指正 / 转载 / 感谢 / 学习这类字眼，或整段没有拉丁字母且不短于 4 个字；`yanao`、`Cilde`、`紫(し)` 这种正常写法不受影响，用户 2026-10-25 要求）。b 站简介还会额外删掉单独成段的整句宣传语。能认 Vocaloid 中文歌词 wiki（`w.atwiki.jp/vocaloidchly`，同时填翻译者与中日歌词）、网易云歌曲（按时间标签把原文与译文**逐行穿插**，填进来就是「一行日文、一行中文」）、bilibili 视频 / 评论 / 专栏 / 动态 / 短链、巴哈姆特創作大廳。**生成第二个条目时这四栏（翻译者 / 翻译链接 / 来源 / 来源链接）会先清空**，只有这一轮查到内容才会重新填上（用户 2026-10-22 报「上一首的来源还留着」）。
6. 点「**完成**」返回整理好的歌词（日语与中文不能同时为空）；「取消」放弃编辑。

**翻译者就是 P 主本人**时不写「`*翻译：人名`」—— 名字在 Songbox 的「P主」里已经有了，站上写成 `*翻译转载自本家视频评论区`（样例：[Short Hand](https://voca.wiki/Short_Hand)）。判定按名字（忽略大小写与空白 / 连字符，也认 VocaDB 的英文名）；来源不是评论区（例如 P 主自己发在网易云）时只去掉署名，来源照旧写成 `*翻译转载自[链接 来源]`。

### 演唱者上色（`LyricsKai/colors`）

1. 在「歌词」页勾选「**使用 LyricsKai/colors**」（在「AI 识别并填入」那一行），歌词改用 `{{LyricsKai/colors}}` 输出（颜色照 voca.wiki 的 [`Module:Vocalist_Colors`](https://voca.wiki/Module:Vocalist_Colors) 取，charas 是本曲歌姬）。
2. 在下方「**歌唱者标记**」面板里点亮某一行右边的歌姬按钮 = 这句是 Ta 唱的（一行可点多个，底色就是该歌姬的颜色）。
3. 左上角「**标记栏**」切日语栏 / 中文栏；两栏标记各存各的，「清空本栏标记」只清当前栏。
4. 两栏行数与**空行位置都一致**时点「**按日语标记中文**」直接按行号照搬（不联网）；行数或空行位置任一不同就交给 AI 对齐行号（需要 `ai_api_key`）—— 行数一样**并不**代表逐行对应（译者把一句拆成三行短句、又在别处并掉两句时，行数照样能相等、位置却全错；用户 2026-10-29 提醒）。
5. 一句里几个人各唱一半时，把光标放在要切开的位置点「**切开**」；点「**合并**」收回切口。

也可以单独运行`python parse_lyrics.py`，只打开「歌词」页并打印生成的歌词段落。

## 提交页（条目 / 模板通用）

1. 左边直接改生成的 wikitext，右边实时预览（在预览里点右键有中文菜单）。`{{bilibiliVideo}}` 在预览里**画成播放器**：站上那个播放器本来靠 Widget 脚本挂 iframe，而桌面预览的浏览器内核（QtWebEngine）**没有 H.264**，iframe 只会显示 bilibili 自己的「您当前的浏览器不支持 HTML5 播放器」（用户 2026-10-27 的截图）。所以预览改成**先取这支视频的封面 / 标题 / UP 主**（公开接口 `x/web-interface/view`，取不到就退回一行链接），再画一张「封面 + 播放按钮 + 标题」的卡片，点封面到 bilibili 看 —— 样子跟站上的播放器一致。手机版预览交给系统浏览器（有 H.264），照旧是真播放器。
2. 点「**提交到 Vocawiki**」（或 `Ctrl+Enter`）：上传封面 → 创建/更新条目 → 创建重定向，并把结果写回本地文件；需要登录（见「账号配置」），未登录时只能预览与编辑。
3. 结果一条一条弹在右下角；提交失败时状态栏变红、窗口保持打开，改完可以再按一次。
4. 「**同步大家族模板**」开关（默认开）：提交成功后把这首歌写进 `== 注释 ==` 里那些模板的对应小节（条目里没有 `== 注释 ==` 时插到末尾那串大家族模板里，点开先显示一份「准备怎么改」的说明，结构认不出就跳过）。
   - **`== 注释 ==` 标题只在有脚注（`<ref>`）时才写**：那一节的唯一作用是承载 `<references/>`，正文没有脚注就只剩几个导航框 —— 用户 2026-10-26 给的《[心淋欲](https://voca.wiki/心淋欲)》diff 275845 → 275851 就是站上编辑把工具写的 `== 注释 ==` 整行删掉、模板留在原处；站上《[Pandora](https://voca.wiki/Pandora)》（ATOLS）也是模板裸放在歌词后面。所以没有脚注时生成的结果是「…歌词 `}}` → 空行 → `{{歌姬模板}}` / `{{活动模板}}` → 空行 → 分类」；有脚注时照旧 `== 注释 ==` + `<references/>` + 模板（参《潘多拉(buzzG)》《binary_biotope》）。
   - 拆成年份子页的歌姬模板（`Template:重音Teto/2025` 那类）按**每个投稿年份**各写一次：2025 年在 niconico 投稿、2026 年又在 YouTube / B 站投稿时，`{{重音Teto/2025}}` 与 `{{重音Teto/2026}}` 都会出现在 `== 注释 ==` 里，年份子页里也各自按**那一年那份稿件**的投稿时间排队。条目注释里的日期照**邻居的写法**写：邻居写 `<!-- 02-22 23:00 -->` 就写月-日时分，邻居写 `<!-- 11-03-16 -->`（带年，如 `Template:猫村伊吕波`）就带上两位年。搬运件、YouTube 自动生成的稿件不算投稿。
   - 按年份分页的歌姬模板**第一档不一定叫 `/2021`**：`Template:可不/2021` 在站上**不存在**，可不 2021 年及以前的歌统一写 `{{可不/2021及以前}}`（2022 起才是 `{{可不/2022}}`、`{{可不/2023}}`…）。以前生成的是不存在的 `{{可不/2021}}`，站上编辑得手动改（用户 2026-10-27 对照《[binary biotope](https://voca.wiki/binary_biotope)》diff 275683 → 275686）。其他按年份分页的歌姬（重音Teto / KAITO / 歌爱雪 / IA / Flower）没有这一档，照旧按年份写。
   - **新条目写在哪、怎么写**（用户 2026-10-28 对照 `Template:IA/2022` 的两笔差异）：
     - **一行一项**：一格是「一行一首」（`条目{{W}}<!--` + `<缩进>-->下一条`）时，新条目**自己占一行**、缩进照邻居 —— 以前直接粘在最后一项同一行（`-->[[Acceleration!!|…]]{{W}}{{lj|[[EDEN…]]}}}}`），站上要再拆开；
     - **整格 `{{lj|…}}` 里不重复套**：外面已经有 `{{lj|` 包着时，新条目写成裸链接 `[[中文|日文]]`，`}}` 留在最后一项行尾；
     - **`{{lj}}` 看原名**：没有被整格包住的平铺列表里，日文原名才套 `{{lj|[[页面|原名]]}}`，英文原名（`EDEN` / `ZERO BLADE`）写裸链接 —— 以前「整段出现过 `{{lj|[[` 就套」，于是英文原名也被套上；
     - **按投稿日期插**：没有 `<!-- 日期 -->` 注释的列表也能按日期排 —— 从各条目的 Songbox（`|nnd_date` / `|bb_date` / `|yt_date`、`{{VOCALOID Songbox/card}}`）现取投稿日（一次批量请求、结果缓存），插到第一个「比本曲晚」的条目之前（本曲 2022-04-21 → 插在 `Noble Rose`(2022-04-22) 之前）；认不出日期就照旧追加到组末。
5. 已下载封面时，提交前会问两句（都用于**文件说明页**）：
   - 封面里出现了哪些歌姬（生成歌姬分类）；
   - **这张封面算谁的**（`[[分类:作者:…]]`）—— 站上惯例是**一张图一个作者**，VocaDB 记了好几位曲绘时（合作曲 / 记错的情况）由你挑一位（最后一项是「都不对（不挂作者分类）」）。只有一位曲绘时不问，直接用它。
6. 点「**清除对话记录**」（输入区那颗红按钮）会清空这一轮的对话、日志与三个编辑器页，并重新开始一轮；「提交」页的内容清空的同时**标签也会重新变灰**，等新一轮跑到提交才有内容。

## 封面图片（自动下载）

- 按分辨率挑来源：niconico 的小图会先换成 360×270 的 `.L`（**没有 `.尺寸` 后缀的老格式同样会换**，否则只有 130×100 —— 用户 2026-10-21 反馈「这图好糊啊」就是这么来的），YouTube / B 站 / 其他来源按实测分辨率比较，自带黑边的让位给干净的。搬运件（VocaDB 的 `Reprint`）也会用。
- 挑完仍偏糊（不足 640×360，例如已被删除的旧曲只有 niconico 的 360×270）时，会**借你自己的 Chrome / Edge 打开稿件页，把页面上声明的封面图重拍一张**（见 `utils/cover_capture.py`）；只有拍出来比原图**更大**才替换。
  - 会**按顺序**试几个候选：当前用的这一版 → **B 站** → 其他。B 站的 API 被风控（或稿件只记在 VocaDB 里）时 `thumb_url` 是空的、`order_covers()` 会把这类稿件整个滤掉，而页面上照样有大图 —— 所以截图这条路对它是必走的（用户 2026-10-23 报「明明该走 B 站截图却没截」）。一张封面都下载不到时也会去拍（拍到了就用它，不再是「没有封面」）。
  - 截不到（页面已 404 / 没装浏览器）就保持原图，并在日志里提示「建议自己截图后在样式页『导入图片』换掉」。取数（VocaDB / AtWiki）失败**不会**连累截图：两条路各有各的开关（`browser_fetch.screenshot_available()`）。
  - 每次截图最多等 25 秒、最多试 3 个来源，不会把生成流程拖成好几分钟。
- 想自己换图：样式页的「**导入图片**」（提交时用这张）或「**AI 提升封面分辨率**」（waifu2x 超分），见上一节。导入的图**不是 JPG 时当场就转**成 JPG（透明的地方铺白底）：预览、AI 取色 / 超分、提交用的都是那份 JPG，保存时直接复制过去当 `<条目名>.jpg`（用户 2026-10-23 要求）。
- 样式页还有「**取该版封面**」：按下拉框里选中的那一版（主版本或某个其他版本，如 Live 版）在各站的稿件重新取一张封面 —— 与生成时同一套逻辑（挑分辨率最大的，偏糊就借浏览器截原图），取到的图直接写成那一版的 `<条目名>(版本短名).jpg`（用户 2026-10-24 要求；以前其他版本只能自己截图再「导入图片」）。这一版已经有封面时会先问一句要不要替换。

## 生成P主模板（侧栏第二个功能）

1. 侧栏「**功能**」选「生成P主模板」（终端模式：`Vocawiki-create-tool --console --producer`）。
2. 按提示给 P主名 / id / `https://vocadb.net/Artist/Details/<id>`（曲目与专辑都取自 VocaDB，年份按**稿件投稿日期**算）。
3. 「曲目」页核对：左边年份列由投稿日期算出，中文条目 / 日文原名 / 投稿日期都能直接改；右边「状态」列显示条目**已建 / 待建**，可点「刷新条目状态」重查；专辑是单独一列清单。
4. 补中文名（都只动**还没中文名**的曲目；「从维基补全条目名」不受开关控制，后两个由 `wikitext.producer_names` 控制）：
   - 「**从维基补全条目名**」：按日文原名搜 voca.wiki，要它自带信息框、自己声明这个歌名；同名但是别人的歌写成 `名字(P主名)`；
   - 「**从外部链接获取中文名**」：网易云 + bilibili 搜日文原名；
   - 「**AI填充中文名**」：问大模型，回来逐个弹窗复检（框里可直接改，「采用并下一个」按改后的写）。

   实在补不出来就在表格里手填（模板里写红链是正常的）。

5. 「样式」页调三组颜色（标题栏 / 分组栏 / 列表 → `{{Navbox}}` 的 `titlestyle` / `groupstyle` / `liststyle`；每格都有「默认」按钮 = 这一项不写）；参考图默认是 P主头像（打开这页自动下载），想换点「选择参考图…」，点「AI 配色」照图配色。
6. 「提交」页点「提交到 Vocawiki」（提交对象是 `Template:<P主名>`，页名 / 模板名能在「曲目」页改）。
7. 生成出来的每个年份格都写成 `|listN = {{lj|{{links|时滞记录{{!}}ラグタイムレコード|…}}}}` —— **`{{lj}}` 只包最外面一层**，`{{links}}` 里的一项是 `中文{{!}}日文` 的裸名字（实测 `Template:Guiano` / `Template:雄之助` 就是这个写法；以前逐项套 `{{lj|日文}}`，用户 2026-10-28 对照 `Template:IA/2022` 那笔差异指出同一件事）。
8. 提交成功后的弹窗：勾选「把 `{{<模板名>|collapsed}}` 加进模板链接的条目」（P主条目排在最前，后面是模板里 `{{links|…}}` 列出的曲目；带 `|collapsed` 让导航框在条目里默认折叠），确认后逐页写入；页面里原来写着裸 `{{<模板名>}}` 的会被**改写成**带 `|collapsed` 的写法，已经是对的就不动；条目还没建或看着不像歌曲条目的页面会灰掉。

## 生成歌姬模板（侧栏第三个功能）

1. 侧栏「**功能**」选「生成歌姬模板」（终端模式：`Vocawiki-create-tool --console --vocalist`）。
2. 按提示给歌姬名（**维基上的条目名**，例如 `歌爱雪` / `重音Teto`）→ 选生成方式 → 选「不拆」时再选一次「其他」栏怎么排：

| 生成方式 | 生成的页面 |
| --- | --- |
| **拆成年份子页，并重写主模板**（默认） | 年份子页 + 文档 + 主模板 |
| **只新建年份子页，不动既有主模板** | 只有年份子页（既有主模板原样不动） |
| **不拆，一个页面写完整** | 一个完整的主模板 |

「其他」栏的排法（选「不拆」时才问，之后还能在「曲目」页上随时勾选切换）：**平铺**（默认，`其他 → 曲目 • 曲目`）或**按年份分层**（`其他 → 2022年 / 2023年 → 曲目`）。拆成年份子页时每页年份已固定，子页里一律平铺。

每格曲目的写法跟站上的年份模板一致（实测 `Template:Flower/2022`、`Template:IA/2021/2023`、`Template:可不/2024`、`Template:重音Teto/2024`、`Template:IA/2022`）：**一行一首** `条目{{W}}<!--` + `<缩进>-->下一条`，且**整格只包一层 `{{lj|…}}`** —— `|list1 = {{lj|[[催眠者|メズマライザー]]{{W}}<!--` … `-->[[医学|イガク]]}}`。以前是逐项套 `{{lj|[[…]]}}`（旧 `Template:歌爱雪/2022` 那种写法），站上会手工收拾掉（用户 2026-10-28 对照 `Template:IA/2022` 的 276359 → 276367 那笔）。翻唱记号 `*`、`<sup>引擎</sup>` 仍在链接外面、`{{lj}}` 里面。

3. 素材自动抓（歌姬所属引擎的殿堂页 + 分类 `Category:<歌姬>歌曲`）；拿不准的曲子会记进「待复核」，在「曲目」页点「**人工复核待定项**」一条一条过（栏 / 站点 / 年份都能改）。
   - 殿堂 / 传说页上的**红链**曲子（条目还没建，所以分类里也没有）：先看**拆分前的主模板**里是否列过（历史版本也算），列过的原样搬回来；剩下的（比如 `炎上的christmas` 这种哪份模板里都没有的）再拿殿堂页给的 PV 编号（`|nnd_id` / `|yt_id` / `|bb_id`）去 **VocaDB** 核对该歌姬的曲库，确认是她唱的才补进来。
   - 这一步要联网翻该歌姬在 VocaDB 上的曲库（限速 1 秒 1 次请求、100 首一页，结果缓存 7 天），翻多少首由 `config.yaml` 的 `vocalist_vocadb_catalog` 决定（默认 6000，`0` = 关掉）；曲库比它大的歌姬只翻最早的这么多首（红链集中在早年）。补进来的曲子**一律进「待复核」**，可以逐条删。
4. 「曲目」页核对：栏 / 站点双击可改（站点写成 `niconico、YouTube`），「删除选中」去掉不该收的曲子，「恢复原样」撤销改动；下面写着会生成哪几个页面与主模板预览（「不拆」时预览那一行还有「**「其他」栏按年份分层**」勾选框）。
5. 「样式」页调三组颜色（与 P主模板共用同一页）；参考图默认是歌姬立绘，点「AI 配色」照它配。改写既有模板时会继承它的样式与「相关人物」那一栏，新建模板从空配色开始。
6. 「提交」页（多页面时顶部有页面选择器，顺序 = 提交顺序）：点「提交到 Vocawiki」（或 Ctrl+Enter）只交当前页，「**全部提交**」按顺序交完还没交过 / 交后又改过的页。
   - **跳过**：这一页不交、直接看下一页（再点一下取消）；年份子页之前传过、或在站上手改过时用它，避免被覆盖。
   - **跳过已存在的**：一次把「维基上已经有」的页全标成跳过（列表里带「维基上已有」标记，跳过后带「已跳过」）；标错了可以在那页点「取消跳过」。
   - 分类页只会在维基上**还没有**时创建（那页可能已经有说明 / 排序键）。
7. 提交成功的弹窗把 `{{<歌姬>/<年份>|collapsed}}` 写进曲子条目、把 `{{<歌姬>|nocate=1}}` 写进歌姬条目。**页面里原来写着别的写法时会被改写成这两者**（主模板 → 对应年份子页、旧年份改到正确年份、少了 `|collapsed` 的补上，并删掉条目里手写的「<歌姬>歌曲」分类），已经是对的就不动；带 `|state=…` 这类参数的写法不碰。

会生成这些页面（拆分时）：

```
Category:<歌姬>模板             ← 年份子页挂的分类页（维基上还没有才建）
Template:<歌姬>/2009 … /2026     ← 年份子页：只列这一年的曲子，分类挂「Category:<歌姬>模板」
Template:<歌姬>/doc              ← 模板文档（分类挂「Category:模板文档」）
Template:<歌姬>                  ← 主模板：相关人物 + 各年份的转接行
```

⚠️ 注意：

- 分类里**最多处理 20000 首**，这个量级请配「只新建年份子页」用（不拆分时「其他」栏会有几千首）；
- 「只新建年份子页」模式下**子页不会自动挂到主模板上**，要自己把 `{{<歌姬>/<年份>|nocate=1}}` 加进去；
- 没有年份的曲子会进待复核，不处理就不会出现在任何页面里。

## 账号配置

1. 登录 Vocawiki，打开「参数设置 → 机器人密码」（或访问`Special:BotPasswords`）。
2. 创建一个机器人密码，授权至少勾选「上传新文件」「编辑现有页面」等权限。
3. 在`wiki_credentials.yaml`中填写（出于安全考虑，建议用**机器人密码**而非主账户密码）：

```yaml
# wiki_credentials.yaml
username: "你的账户名@机器人名"     # 例如 TimeRen@tool
password: "机器人密码"
```

未登录时仍可预览与编辑，只是无法提交。

## 自己构建（打包 exe）

Windows 上双击 **`build.bat`** 就能打包（先找 Python，优先项目自带的 `.venv`；缺依赖时自动 `pip install -r requirements.txt`，再调 `build.py`）：

```bat
build.bat 1.3.1      :: 直接打包 1.3.1
build.bat            :: 不带版本号时会问一次（回车用 0.0.0）
build.bat --check    :: 只检查 Python 与依赖，不打包
```

打包完会问一句「是否同时生成 Android APK」（答 `y` 才继续，直接回车跳过）。想跳过这句问答就用参数：

```bat
build.bat 1.3.1 --with-apk            :: 打完 exe 顺便生成 debug APK
build.bat 1.3.1 --with-apk --release  :: 顺便生成签名的 release APK
build.bat 1.3.1 --no-apk              :: 只打 exe，不问也不生成 APK
```

`--with-apk` 时 APK 的版本号跟着 exe 走（没写版本号就用 `build.py` 问出来的那个）；没有交互终端（CI、`<nul`、管道）时不会停下来问，默认跳过 APK，要生成就显式加 `--with-apk`。

Linux / macOS 走同一个 `build.py`：

```bash
make build VERSION=1.3.1     # 或 make build（会问版本号）
make source                  # 源码包
./make_source.sh 1.3.1       # 同上，只是不开头走 make
python build.py 1.3.1        # 直接调脚本（依赖需已装好）
```

发布包只在项目根目录生成 `Vocawiki-create-tool (版本号).zip`（exe + 运行时资源，解压即用），两个包里的 `wiki_credentials.yaml` 都是**清空过密钥的模板**。程序图标放 **`assets/icon.png`** 即可，打包时自动转成 `assets/icon.ico` 并嵌进 exe。打包时还会生成 `_build_info.py`（版本号 / 构建时间 / 提交号，`.gitignore` 里有它），设置页的「检查更新」靠它报当前版本。

把代码推到 `master` 后，GitHub Actions 会先跑一遍单元测试（`tests/` 下除两套界面测试之外的全部用例），通过后再更新**同一个**「最新构建」release（tag 固定 `latest`，里面的 `Vocawiki-create-tool-latest.apk` 与 `…-latest.zip` 每次覆盖，不会按推送建一堆 release）：先换 APK，随后一个 Windows 作业再把 exe 的 zip 换上去（最后还会核对 zip 大小与 commit，`exe` 失败会让整个 run 变红，不再静默保留旧 zip）。只改 `tests/` 的提交只跑测试、不重出包也不顶版本号。这个 release 标成 **prerelease**，所以仓库页面上「Latest」仍然是你自己发的 `v2.4.0` 那类正式版；版本号取现存最高版本、把补丁位换成工作流序号（`v2.4.0` → `2.4.28`），保证滚动构建永远排在新正式版之后。装在别人机器上的程序点「设置 → 程序更新」就能直接升级，不用再手动重新封装。

## 自己构建（Android APK）

Android 版是独立的 **Kivy** 界面（`mobile/`），复用同一套生成逻辑；桌面 PyQt5 构建不受影响。Buildozer 不能在原生 Windows 上运行，需要 **WSL2 + Ubuntu**。还没装 WSL 的话，先在**管理员 PowerShell**里执行（然后重启）：

```powershell
wsl --install -d Ubuntu-22.04
```

```bat
build.bat --check apk     :: 检查 WSL / Ubuntu / Buildozer / Java 17
build.bat apk 1.3.1       :: 只生成 debug APK（不打包 exe）
build.bat apk --release 1.3.1
```

只想顺便在打 exe 时生成 APK，不用 `apk` 模式（那会只做 APK）：`build.bat 1.3.1 --with-apk`。双击 `build.bat` 时会先打完 exe 再问一句要不要继续生成 APK。

WSL 里装 `Ubuntu` 或 `Ubuntu-22.04` 都行（`ubuntu-22.04` 与 CI 用的一致，最稳）；`build.bat` 会自动探测已安装的发行版名。

第一次构建前，先在 WSL/Ubuntu 里装好工具链（`build.bat` 会自动使用 `~/.buildozer-venv`）：

```bash
sudo apt update
sudo apt install -y python3 python3-venv openjdk-17-jdk unzip git zip
python3 -m venv "$HOME/.buildozer-venv"
"$HOME/.buildozer-venv/bin/pip" install --upgrade pip buildozer cython
echo 'export PATH="$HOME/.buildozer-venv/bin:$PATH"' >> ~/.bashrc
```

release 包需要签名密钥；可以在 Windows 侧设置，`build.bat` 会通过 `WSLENV` 传进 WSL：

```bat
set P4A_RELEASE_KEYSTORE=C:\path\release.keystore
set P4A_RELEASE_KEYSTORE_PASSWD=你的密码
set P4A_RELEASE_KEYALIAS=你的别名
build.bat apk --release 1.3.1
```

第一次构建会由 Buildozer 下载 Android SDK/NDK，耗时且占磁盘。产物在项目根目录：`Vocawiki-create-tool (版本号).apk`，目标为 **Android 8.0+ / arm64-v8a**。

不想装 WSL 时，可以把代码推到 GitHub，在 Actions 里手动运行 **Build Android APK**（或直接 push 到 master），构建完成后下载 `vocawiki-apk` artifact。

Android 版的差异：

- 竖屏、单窗口；所有页面都是可上下滚动的长列表。
- 「设置」页最上面有**深色模式**开关（写进 `config.yaml` 的 `dark_mode`，切完立即生效）；界面配色集中在 `mobile/screens/common.py` 的 `THEMES` 里，亮 / 暗各一套。
- 「设置」页还能**导入 `config.yaml` / `wiki_credentials.yaml`**：从手机里挑一份文件覆盖应用目录里的同名文件（旧文件自动备份成 `.bak`），导入 `config.yaml` 后立刻重新读取（深浅色跟着变）。Android 上走系统的存储访问框架（`ACTION_OPEN_DOCUMENT`），不需要存储权限；文件类型不对（比如把凭据当配置导入）会被拒绝、现有设置不动。文件内容是**逐字节**读出来的（`read()` 返回 0…255）：早先用 jnius 的 `byte[]` 中转，字节是有符号的（-128…127），带中文注释的 `config.yaml` 一律读失败，导入按钮就只会报错（用户 2026-10-21 报）；读失败现在会显示具体原因，而不是当成「已取消导入」。
- **生成歌曲条目时会先走一屏「样式」页**（改 Songbox / 简介 / 歌词的颜色与样式、导入或 AI 超分封面、给其他版本单独配色），和桌面版「样式」标签页对应；不想要它就在设置里关掉「生成后调样式」（写的是 `config.color.color_editor`）。「导入封面」选的图不是 JPG 时会**当场转成 JPG**（透明处铺白底），预览 / 超分 / 提交都用它。
- 长文本框（歌词、wikitext）**跟着内容长高**，整页上下滚动浏览与修改；不再固定在 180dp 里抠着看。
- 歌词页多了「**比对中日歌词**」：手机屏放不下并排两栏，点它开一页逐行比对 —— 每行上面是日文、下面是中文，两边都能直接改；「✕」删掉这一行、「＋」在它后面插一行，顶部会提示「N 行没有译文 / 中文里还带着假名」这类问题，改完点「完成」写回日语 / 中文两栏（配对规则见 `mobile/lyrics_compare.py`）。
- 提交预览交给系统浏览器：预览文档由应用内的 127.0.0.1 小服务提供（Android 不允许把 `file://` 交给浏览器），点「预览」会自动开浏览器读到渲染结果。
- 封面 AI 超分只走在线 waifu2x，不打包 onnxruntime 与 numpy（黑边检测改用纯 PIL）。
- 没有桌面 Chrome/Edge 可借，Cloudflare 拦截时会先试系统自带的 `curl`，两边都不行就退回手动粘贴 / 手动链接。
- 配置、日志、输出都在应用私有目录；设置页可填账号、密码与 AI 密钥。

构建用的是 python-for-android 的 **v2024.01.21**（CPython 3.11 + NDK 25b）而不是 master：
master 已经升到 CPython 3.14，而 Kivy 2.3.x 在 3.14 上会启动即闪退。

APK 打开就闪退时的排查办法：

```bash
adb logcat -s python:V SDL:V AndroidRuntime:E   # 手机上要开 USB 调试
adb shell run-as wiki.voca.vocawikitool cat files/crash.log   # debug 包可直接读崩溃栈
```

启动阶段的异常都会写进上面那个 `crash.log`（界面里的「查看日志」也能看到运行期日志）。
